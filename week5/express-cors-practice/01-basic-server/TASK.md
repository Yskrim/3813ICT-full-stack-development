# Task 1 — Basic Express server

Цель: с нуля поднять Express-сервер, раздать статику и один JSON-эндпоинт.
CORS тут не нужен — сервер и "клиент" на одном origin.

## Требования

1. `npm install`, затем `npm run dev` поднимает сервер на порту `3000`.
2. `app.use(express.static(...))` раздаёт файлы из папки `www/`.
3. Запрос `GET http://localhost:3000/` отдаёт `www/index.html`.
4. Роут `GET /api/status` возвращает JSON:
   ```json
   { "status": "ok", "time": "<ISO-строка текущего времени>" }
   ```
5. Любой несуществующий путь должен возвращать `404` с телом
   `{ "error": "Not found" }` (не HTML-страницу Express по умолчанию).

## Проверка

```bash
curl http://localhost:3000/api/status
curl -i http://localhost:3000/does-not-exist   # ожидаем 404 и JSON
```

Открой `http://localhost:3000/` в браузере — должна показаться `index.html`.

## Вопрос на понимание

Почему `express.static` обычно регистрируют middleware'ом ДО роутов, а
обработчик 404 — самым ПОСЛЕДНИМ в цепочке `app.use`/`app.get`? Что будет,
если поставить 404-обработчик первым?

Потому что статик должен сработать перед выполнением любого другого маршрута, чтобы АПИ эндпоинтам было откуда передавать страницы/сохранять файлы. Потом идут сами маршруты, после выполнения которых, сервер возвращается в слушающее состояние. В самом конце идет обработчик ошибки, то есть любой другой маршрут, который не описывается приложением. Так как весь код выполняется последовательно, пока эндпоинт подходит, он выполнится до, а если ни один не подошел, сервер вернет ошибку.

Если передать обработчик ошибок в самое начало, любой путь будет восприниматься как ошибочный, потому что по порядку сверху стоит catch-all
