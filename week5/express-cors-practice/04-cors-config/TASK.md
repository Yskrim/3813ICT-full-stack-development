# Task 4 — Fine-grained CORS config + preflight

Цель: не просто "включить CORS для всех", а настроить его точечно, и увидеть
реальный preflight-запрос (`OPTIONS`) в Network-панели.

Снова два процесса: `server/` (порт 3000) и `client/` (порт 5500).

## Требования к серверу (`server/server.js`)

1. Ресурс `items` в памяти: `{ id, name }`.
2. `GET /api/items` — публичный, доступен с любого origin.
3. `PUT /api/items/:id` — требует заголовок `X-Api-Key: secret123`.
   Если заголовка нет или он неверный — `401 { "error": "invalid api key" }`.
4. `DELETE /api/items/:id` — то же требование по `X-Api-Key`.
5. Настрой `cors()` с опциями (не пустой `cors()`!):
   - `origin`: разрешён только `http://localhost:5500`.
   - `methods`: `GET, PUT, DELETE`.
   - `allowedHeaders`: должен включать `Content-Type` и `X-Api-Key`.

Документация опций: https://www.npmjs.com/package/cors

## Что проверить в браузере (client на :5500)

1. Открой DevTools → Network, включи "Preserve log".
2. Нажми кнопку "PUT with API key" на странице клиента.
3. Ты должен увидеть **два** запроса: `OPTIONS /api/items/:id` (preflight),
   затем `PUT /api/items/:id`. Открой preflight-запрос и посмотри его
   заголовки ответа (`Access-Control-Allow-Methods`,
   `Access-Control-Allow-Headers`).
4. Нажми кнопку "PUT without API key" — сервер должен ответить `401`, но
   preflight всё равно пройдёт (почему — см. вопрос 2 ниже).
5. Временно поменяй порт клиента на что-то другое (например, отредактируй
   `client/package.json`, поставь `5501`) и убедись, что теперь запросы с
   этого origin блокируются.

## Вопросы на понимание

1. Почему `GET /api/items` не вызывает preflight, а `PUT` и `DELETE` —
   вызывают? Что в спецификации CORS называется "simple request"?
2. Preflight (`OPTIONS`) проверяет только origin/метод/заголовки на уровне
   CORS — почему он не может знать заранее, что API-ключ неверный и что
   основной запрос всё равно получит 401?
3. Если бы мы хотели разрешить несколько origin (например, и `:5500`, и
   `:4200`), как это делается в `cors()` — можно ли просто перечислить массив
   строк в `origin`?


   1. Потому что GET это публичный метод (simple request), для которого не нужен preflight. А, по условию, PUT и DELETE - это методы, требующие проверки ключа и ориджин, поэтому вызывается middleware app.options('/api/items/:id', cors(corsOptions)) для передачи кастомных настроек поведения в экспресс и затем на методах, передается requireApiKey и cors(corsOptions) как preflight, который должен выполниться до основного метода.

   2. Потому что у корс нет такого функционала. Он только проверяет доступ по ориджин. Поэтому мы пишем свой обработчик хедера, чтобы проверить ключ до возвращения ответа сервера.

   3. нужно описать допустимые ориджин в массиве allowedOrigins[ "", "" ]; в начале файла сервера или отдельном модуле. Просто передать массив не получится, потому что нужно провалидировать входящий ориджин против массива допускаемых через коллбэк. Если мы узнаем, что входящий есть в массиве, пропускаем его дальше для методов methods:[].
