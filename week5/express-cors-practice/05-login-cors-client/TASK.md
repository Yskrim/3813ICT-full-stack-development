# Task 5 — Login API + CORS-client with localStorage

Цель: собрать в миниатюре то же самое, что реальный Workshop 5 просит сделать
в Angular (`week5/Workshop/Workshop 5.pdf`, задачи 2-4), но на чистом
HTML/JS — чтобы отработать связку Express + CORS + fetch + localStorage
ДО того, как усложнять всё Angular-ом.

Два процесса: `server/` (порт 3000, `/api/auth`) и `client/` (порт 5500,
обычный HTML/JS, без фреймворка).

## Сервер (`server/routes/auth.js`)

1. Класс `User` с полями: `username, birthdate, age, email, password, valid`.
2. Массив из 3 пользователей (сам придумай данные).
3. `POST /api/auth` принимает `{ username, password }`.
   - Если есть совпадение по username+password — ответ `200` с объектом
     пользователя, где `valid: true`, но **без поля `password`**.
   - Если совпадения нет — ответ `200` с `{ valid: false }` (не 401 — так
     сказано в задании Workshop 5, потому что фронт сам решает что показать).
4. Подключи `cors()` для origin `http://localhost:5500`.

## Клиент (`client/public/`)

- `index.html` — форма логина (username + password). По сабмиту:
  `fetch("http://localhost:3000/api/auth", { method: "POST", ... })`.
  - Если `valid === true` — сохрани пользователя в `localStorage`
    (`JSON.stringify`) и перенаправь на `profile.html`.
  - Если `valid === false` — покажи сообщение об ошибке на странице логина.
- `profile.html` — при загрузке читает пользователя из `localStorage`
  (`JSON.parse`).
  - Если в `localStorage` пусто — редирект обратно на `index.html`
    (аналог AuthGuard из задания Workshop 5).
  - Показывает поля пользователя в форме, разрешает их отредактировать и
    сохранить обратно в `localStorage` (кнопка "Save" — без похода на сервер,
    просто перезаписать localStorage).
  - Кнопка "Log out" — очищает `localStorage` и редиректит на `index.html`.

## Проверка

1. Залогинься валидными данными одного из 3 пользователей — должен открыться
   `profile.html` с его данными.
2. Обнови страницу профиля (F5) — данные должны остаться (значит, реально
   лежат в localStorage, а не только в памяти JS).
3. Отредактируй поле, сохрани, обнови страницу — изменения должны сохраниться.
4. Нажми Log out, попробуй открыть `profile.html` напрямую по URL — должен
   перекинуть на логин.
5. Попробуй логин с неверным паролем — должна показаться ошибка, без
   перехода на profile.html.

## Вопросы на понимание

1. Почему пароль ни в каком виде не должен попадать в `localStorage`, даже
   если он не в открытом виде хранится на сервере?
2. `localStorage` живёт только в конкретном браузере на конкретном
   компьютере. Чем это отличается от куки/сессии на сервере — и почему для
   этого задания это ок, а для настоящей аутентификации в проде — нет?
3. Если бы `/api/auth` при неверном пароле возвращал `401` вместо
   `200 { valid: false }` — что пришлось бы поменять в клиентском `fetch`,
   чтобы обработка ошибки продолжала работать?
