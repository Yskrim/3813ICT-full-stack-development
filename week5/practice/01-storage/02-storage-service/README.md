# 1.2 — StorageService и настройки

**Тема:** хранилища браузера (5_1)
**Место в теме:** второе из трёх, связка концептов
**Время:** 40–60 минут
**Опирается на:** [1.1 — Хранилища в консоли](../01-console-storage/README.md)
**Дальше:** [1.3 — Сессия пользователя без сервера](../03-user-session/README.md)

## Задача

В 1.1 ты увидел три ловушки: объекты нужно превращать в JSON, `getItem` может вернуть `null`, а испорченная строка сломает `JSON.parse`. Если помнить об этом в каждом компоненте, рано или поздно где-то забудешь. Правильный ход — один раз написать **сервис**, который учитывает всё это, а остальной код будет просто вызывать `get` и `set`.

Первым пользователем этого сервиса станут настройки интерфейса: тема оформления, размер шрифта и последний открытый канал. Их удобно хранить одним объектом, и у них есть значения по умолчанию, которые должны подставляться, если в хранилище ничего нет или там мусор.

Этот `StorageService` дальше станет фундаментом: в 1.3 на нём будет держаться сессия пользователя, а в 2.3 — `AuthService`.

## Зачем это задание

Работа с хранилищем через один сервис — стандартная практика: если завтра понадобится хранить данные иначе, изменится один файл. Кроме того, здесь ты впервые соберёшь вместе JSON, обработку `null` и `try/catch` — то, что по отдельности уже видел в консоли.

## Что проверяет

1. Ты умеешь сериализовать и десериализовать объекты через JSON.
2. Ты обрабатываешь отсутствующий ключ и испорченные данные, не роняя приложение.
3. Ты умеешь объединять сохранённые значения со значениями по умолчанию.
4. Ты понимаешь, что данные переживают F5 именно благодаря хранилищу.

## Старт

```bash
ng g s services/storage
ng g s services/preferences
```

Если CLI создал файлы без суффикса (`storage.ts`, класс `Storage`) — вернись к [подготовке, шаг 1](../../00-setup/README.md) и включи суффиксы: класс с именем `Storage` конфликтует со встроенным типом браузера.

Интерфейс настроек (положи его в `preferences.service.ts`):

```ts
export interface Preferences {
  theme: 'light' | 'dark';
  fontSize: number;              // в пикселях
  lastChannelId: number | null;
}
```

## Что сделать

**Часть А — `StorageService`**

Сервис с тремя методами:

- `get<T>(key)` — возвращает сохранённый объект или `null`, если ключа нет **или** данные испорчены;
- `set(key, value)` — сохраняет любое значение; если сохранить не удалось (например, закончилось место), не роняет приложение, а пишет предупреждение в консоль;
- `remove(key)` — удаляет ключ.

**Часть Б — `PreferencesService`**

1. Внедри `StorageService` через `inject()`.
2. Заведи значения по умолчанию: светлая тема, 16 px, канала нет.
3. Метод `load()` возвращает настройки: сохранённые поля поверх значений по умолчанию. Если сохранено только `{ theme: 'dark' }`, результат должен содержать и `fontSize: 16`.
4. Метод `update(changes)` принимает **часть** настроек, объединяет с текущими и сохраняет.
5. Метод `reset()` удаляет настройки из хранилища.

**Часть В — проверка на площадке**

На странице `playground` добавь кнопки «Тёмная тема», «Шрифт +2», «Выбрать канал 5», «Сбросить» и вывод текущих настроек. Затем:

1. Нажми кнопки и перезагрузи страницу — настройки на месте?
2. В Application вручную испорти JSON (например, удали закрывающую скобку) и перезагрузи — приложение не падает, показаны значения по умолчанию?
3. Удали ключ вручную — снова значения по умолчанию?

## Критерии готовности

- [ ] После F5 настройки восстанавливаются
- [ ] Испорченный JSON и отсутствующий ключ дают значения по умолчанию, в консоли нет необработанных ошибок
- [ ] `update({ fontSize: 18 })` не затирает `theme` и `lastChannelId`
- [ ] Компонент площадки не обращается к `localStorage` напрямую — только через сервисы
- [ ] Ты можешь ответить: зачем `try/catch` вокруг `JSON.parse` и вокруг `setItem` — от каких двух разных проблем они защищают?
- [ ] Ты можешь ответить: почему `get<T>` не проверяет, что данные действительно имеют тип `T`?

## Наводящие вопросы (если застрял)

- Что вернёт `getItem`, если ключа нет? Что будет, если передать это в `JSON.parse`?
- Какие исключения может бросить `setItem`? А `JSON.parse`?
- Как объединить два объекта так, чтобы поля второго перекрыли поля первого? (Вспомни spread `{ ...a, ...b }`.)
- Где должны лежать значения по умолчанию, чтобы их нельзя было случайно изменить снаружи?

## Типичные ловушки

- `JSON.parse(localStorage.getItem(key))` без проверки — работает, пока данные в порядке, и падает, как только их кто-то испортит.
- Хранение настроек тремя отдельными ключами — их труднее обновлять и удалять вместе.
- `update`, который сохраняет только переданные поля, — остальные настройки пропадут.
- Возврат из `load()` того же объекта, что лежит внутри сервиса: снаружи его можно случайно изменить.
