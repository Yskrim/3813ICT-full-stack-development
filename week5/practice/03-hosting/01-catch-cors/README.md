# 3.1 — Поймать CORS

**Тема:** хостинг и CORS (5_3)
**Место в теме:** первое из трёх, базовый концепт
**Время:** 30–40 минут
**Опирается на:** [00 — Подготовка проекта](../../00-setup/README.md)
**Дальше:** [3.2 — Прокси вместо CORS](../02-proxy/README.md)

## Задача

Ошибку CORS рано или поздно встречает каждый, кто соединяет фронтенд и бэкенд, и обычно в самый неудобный момент. Её сообщение выглядит пугающе, а решение из интернета «поставь `cors()`» работает, но не объясняет, что произошло.

Сейчас ты вызовешь эту ошибку специально, в спокойной обстановке, и разберёшь по шагам: дошёл ли запрос до сервера, кто его заблокировал, почему для одного запроса в Network видно два, и что именно меняет пакет `cors`. HttpClient пока не нужен — запросы будем отправлять через `fetch` прямо из консоли браузера.

## Зачем это задание

Когда понимаешь механизм, ошибка CORS перестаёт быть загадкой: по консоли и вкладке Network сразу видно, чего не хватает. Это сэкономит часы в Phase 2.

## Что проверяет

1. Ты понимаешь, что same-origin policy блокирует чтение ответа, а не сам факт запроса.
2. Ты отличаешь простой запрос от запроса с preflight.
3. Ты умеешь подключить `cors` с конкретным origin и понимаешь, что это разрешение, а не защита.
4. Ты знаешь, что CORS проверяет только браузер.

## Старт

В папке `server`:

```bash
npm install cors
```

Добавь в `server.js` два маршрута (перед `app.listen`). Логирование в начале покажет, какие запросы реально доходят до сервера:

```js
// Каждый запрос, дошедший до сервера, — в консоль
app.use((req, res, next) => {
  console.log(new Date().toISOString(), req.method, req.url, 'Origin:', req.get('origin') ?? '—');
  next();
});

app.get('/api/ping', (req, res) => res.json({ pong: true }));

app.post('/api/echo', (req, res) => res.json({ youSent: req.body }));
```

Важно: логирующий middleware должен стоять **выше** маршрутов. `cors` пока не подключай.

Запусти `npm run dev` в `server` и `ng serve` в корне проекта. Открой http://localhost:4200 и консоль DevTools.

## Что сделать

Записывай наблюдения в `observations.md`: что в консоли браузера, что во вкладке Network, что в консоли сервера.

**Часть А — простой запрос**

```js
await fetch('http://localhost:3000/api/ping').then((r) => r.json());
```

1. Что написал браузер? Дошёл ли запрос до сервера (смотри его консоль)?
2. Что во вкладке Network у этого запроса?

**Часть Б — запрос с preflight**

```js
await fetch('http://localhost:3000/api/echo', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ text: 'hi' }),
}).then((r) => r.json());
```

1. Сколько запросов в Network и каких методов?
2. Какой запрос дошёл до сервера, а какой — нет?

**Часть В — не браузер**

```bash
curl http://localhost:3000/api/ping
curl -X POST http://localhost:3000/api/echo -H "Content-Type: application/json" -d '{"text":"hi"}'
```

Что ответил сервер? Почему здесь нет никакой ошибки?

**Часть Г — разрешение**

1. Подключи `cors` так, чтобы разрешён был **только** `http://localhost:4200`. Повтори опыты А и Б.
2. Найди в Network заголовок ответа, который добавил `cors`.
3. Запусти Angular на другом порту (`ng serve --port 4300`), повтори опыт А оттуда.
4. Перенеси `app.use(cors(...))` **ниже** маршрутов и повтори опыт А с 4200. Потом верни на место.

## Критерии готовности

- [ ] В `observations.md` для каждой части записано, что видно в браузере, в Network и на сервере
- [ ] `cors` разрешает только `http://localhost:4200` и стоит до маршрутов
- [ ] Ты можешь ответить: дошёл ли GET из части А до сервера? Кто и что заблокировал?
- [ ] Ты можешь ответить: почему для POST с JSON браузер отправил два запроса?
- [ ] Ты можешь ответить: почему curl работает без всякого CORS и что из этого следует для безопасности сервера?

## Типичные ловушки

- Вывод «запрос не дошёл», сделанный только по консоли браузера, без проверки консоли сервера.
- `cors()` без настроек — работает, но разрешает всем.
- `cors` после маршрутов — ответы уходят без заголовков.
- Путаница между `origin` в настройках `cors` (кто может читать) и адресом самого сервера.
