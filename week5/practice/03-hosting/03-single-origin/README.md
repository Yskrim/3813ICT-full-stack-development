# 3.3 — Single origin и F5

**Тема:** хостинг и CORS (5_3)
**Место в теме:** третье из трёх, рабочий кусок Phase 2
**Время:** 40–60 минут
**Опирается на:** [3.2 — Прокси вместо CORS](../02-proxy/README.md), [2.3 — AuthService и гарды ролей](../../02-services/03-auth-guards/README.md)
**Дальше:** [4.1 — Observable руками](../../04-http/01-observables/README.md)

## Задача

Проверяющий Phase 2 не будет запускать два сервера и настраивать прокси. Удобнее всего, когда приложение собрано и одна команда поднимает один сервер, который отдаёт и страницы, и API. Это режим **single origin**.

Собрать приложение и указать Express папку со сборкой — дело двух строк. Но в этом режиме есть ловушка, которую материал курса не показывает: пока ходишь по ссылкам внутри приложения, всё работает, а стоит нажать F5 на `/channels` — и сервер отвечает `Cannot GET /channels`. Сейчас ты разберёшься, почему, и сделаешь так, чтобы любой маршрут Angular открывался и по прямой ссылке, и после перезагрузки.

## Зачем это задание

Это финальная конфигурация сервера для сдачи. К тому же здесь хорошо видно, чем маршрут Angular отличается от маршрута Express, — путаница между ними частая.

## Что проверяет

1. Ты знаешь, где лежит сборка Angular 17+ и как её раздать через `express.static`.
2. Ты понимаешь, зачем нужен fallback и почему он должен быть последним.
3. Ты знаешь синтаксис «любого пути» в Express 5.
4. Ты строишь пути к файлам от `__dirname`.

## Старт

```bash
ng build
```

Посмотри, что появилось в `dist/chat-practice/` — где именно лежит `index.html`?

## Что сделать

**Часть А — раздать сборку**

1. В `server.js` раздай папку со сборкой через `express.static`. Путь строй от папки самого файла `server.js`.
2. Добавь при запуске сервера проверку: если `index.html` по этому пути нет — предупреждение в консоль.
3. Открой http://localhost:3000 — должно открыться приложение. Пройди по ссылкам.

**Часть Б — сломать и починить F5**

1. На `http://localhost:3000/channels` нажми F5 (или открой этот адрес в новой вкладке). Что ответил сервер?
2. Добавь fallback, чтобы любой `GET`, который не является API и не нашёлся среди файлов, получал `index.html`.
3. Проверь F5 на `/channels`, `/admin`, `/services-lab`.

**Часть В — API не должен получать HTML**

1. Открой http://localhost:3000/api/unknown. Что пришло?
2. Сделай так, чтобы неизвестный адрес под `/api` получал JSON с кодом 404, а не `index.html`.

**Часть Г — одна команда**

Добавь в `package.json` корня скрипт, который собирает Angular и запускает сервер.

**Часть Д — наблюдение**

Войди в приложение на `localhost:4200`, затем открой `localhost:3000`. Вошёл ли ты там? Вспомни 1.1 и объясни.

## Критерии готовности

- [ ] `http://localhost:3000` открывает приложение, API работает
- [ ] F5 и прямые ссылки на любые маршруты Angular работают
- [ ] `/api/unknown` отвечает JSON 404
- [ ] Порядок в `server.js`: API → статика → fallback
- [ ] Собрать и запустить можно одной командой
- [ ] Ты можешь ответить: почему без fallback переходы по ссылкам работают, а F5 — нет?
- [ ] Ты можешь ответить: почему в Express 5 нельзя написать `app.get('*', ...)`?
- [ ] Ты можешь ответить: что будет, если fallback поставить перед `express.static`?

## Типичные ловушки

- Путь к `dist` без подпапки `browser`.
- Относительный путь `'../dist/...'` без `__dirname` — сервер ломается при запуске из другой папки.
- Fallback выше API — все запросы к API получают `index.html`.
- Забыли пересобрать Angular после изменений и удивляетесь, что на 3000 всё по-старому.
