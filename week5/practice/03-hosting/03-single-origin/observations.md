### Часть А — раздать сборку

1. В server.js раздай папку со сборкой через express.static. Путь строй от папки самого файла server.js.

```js
// static files
  app.use(express.static(path.join(__dirname, '../dist/chat-practice/browser')));
// 
```

2. Добавь при запуске сервера проверку: если index.html по этому пути нет — предупреждение в консоль.
```js

  if(!fs.existsSync(path.join(__dirname, '../dist/chat-practice/browser', 'index.html'))){
    console.warn('index.html not found at required path');
  }
```

3. Открой http://localhost:3000 — должно открыться приложение. Пройди по ссылкам.

  - Приложение запускается
  - Ссылки кликаются и логика выполняется
  - API эндпоинты отвечают и реагируют.

### Часть Б — сломать и починить F5

1. На http://localhost:3000/channels нажми F5 (или открой этот адрес в новой вкладке). Что ответил сервер?
  - сервер отвечает ошибкой 404 (Not Found) -- состояние приложения не сохраняется между рефрешами.


2. Добавь fallback, чтобы любой GET, который не является API и не нашёлся среди файлов, получал index.html.

```js
// fallback
  app.get('/{*splat}', (req,res) => {
    res.sendFile(path.join(__dirname, '../dist/chat-practice/browser', 'index.html'));
  });
// 
```
  - Любой запрос гет получает index.html 

3. Проверь F5 на /channels, /admin, /services-lab.

  - Рефреш работает на любой странице и не вызывает ошибки.
  - Рефреш отдает стартовую страницу приложения при каждой загрузке
  - Ангулар запускается заново, читает путь, читает хранилище, и отдает нужную страницу и нужное состояние == перевычисляет заново все состояние приложения по признакам, которые ему доступны для считывания (адресная строка, storage и повторные запросы к серверу за данными* (пока их нет, но скоро появятся)).

### Часть В — API не должен получать HTML

1. Открой http://localhost:3000/api/unknown. Что пришло?
  - Переход на неизвестный апи вызывает fallback
  - В консоли выходит ошибка NG04002

2. Сделай так, чтобы неизвестный адрес под /api получал JSON с кодом 404, а не index.html.

```js
  // Unknown api
  app.use('/api', (req, res) => {
    res.status(404).json({ error: "API ENDPOINT NOT FOUND. RESPONSE FROM MY API" });
  });
```
  - Теперь любой неизвестный апи вызывает конкретный маршрут на сервере, который выводит ошибку запроса без fallback

### Часть Д — наблюдение

1. Войди в приложение на localhost:4200, затем открой localhost:3000. Вошёл ли ты там? Вспомни 1.1 и объясни.

- простой переход не проходит, потому что дев сервер не был запущен
- с дев сервером: 
    1. так как у нас настроен прокси, дев сервер ведет все апи запросы через порт 3000
    2. Так как ориджины разные, данные сессии сохраняются в браузере для разных ориджин. Поэтому вход через 4200 не отображается на 3000, хотя обрабатывается все тем же сервером.

    Эту ситуацию вряд ли можно назвать двумя разными пользователями для одного сервера, потому что дев сервер все равно обманывает браузер своим прокси, и корс его не затрагивает.
    Можно было бы назвать это двумя разными сессиями, если оба клиента заходили через версию билда.


    Поправки ответов: 
    - Правильно про разные ориджин для браузера. 
    - Сервер не участвует в обработке логина (пока что), поэтому не имеет значения в этом контексте. Вся логика логина живет в ангулар.
    - Из этого следует, что прокси так же не при чем - сервер ничего не обрабатывает и прокси делать нечего.
    - Корс тоже не при делах, корс не регулирует доступ к хранилищу. Никакие заголовки не поменяют того, что локалСторадж не доступен другому ориджину.

    Если бы использовался куки, то браузер вел бы себя иначе, потому что кука привязывается к хосту, а не порту. Любая новая вкладка в том же браузере читала бы куку и открывала профиль только одного пользователя.
