# 3.2 — Прокси вместо CORS

**Тема:** хостинг и CORS (5_3)
**Место в теме:** второе из трёх, связка концептов
**Время:** 25–35 минут
**Опирается на:** [3.1 — Поймать CORS](../01-catch-cors/README.md)
**Дальше:** [3.3 — Single origin и F5](../03-single-origin/README.md). С этого задания все запросы из Angular идут по адресу `/api/...`

## Задача

В 3.1 CORS заработал, но осталось неудобство: в Angular-коде придётся писать полный адрес `http://localhost:3000/api/...`, а после сборки (в 3.3) приложение и API окажутся на одном сервере, и адрес станет просто `/api/...`. Значит, перед сдачей пришлось бы переписывать все сервисы или заводить переключатель.

Есть способ проще: пусть сервер разработки Angular сам пересылает запросы на `/api` в Express. Тогда для браузера всё приходит с `localhost:4200` — одного origin, — CORS не нужен вовсе, а адрес API в коде одинаков в обоих режимах. Это и есть прокси `ng serve`.

## Зачем это задание

Этот режим разработки будет основным для всех следующих заданий и для Phase 2. Один раз настроил — и больше не думаешь ни о CORS, ни об адресах.

## Что проверяет

1. Ты понимаешь, почему прокси убирает проблему разных origin.
2. Ты умеешь настроить прокси в `ng serve` и подключить его в `angular.json`.
3. Ты понимаешь, что прокси работает только в режиме разработки.

## Старт

1. Убери из `server.js` подключение `cors` (сам пакет можно оставить — пригодится для сравнения).
2. Создай в корне Angular-проекта пустой файл `proxy.conf.json`.

## Что сделать

**Часть А — прокси**

1. Настрой `proxy.conf.json` так, чтобы все запросы на `/api` пересылались на `http://localhost:3000`.
2. Подключи его в `angular.json` в настройках `serve`, чтобы не писать флаг при каждом запуске.
3. Перезапусти `ng serve` (изменения в `angular.json` без перезапуска не подхватятся).

**Часть Б — проверка**

В консоли на `http://localhost:4200`:

```js
await fetch('/api/ping').then((r) => r.json());
await fetch('/api/echo', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ text: 'hi' }),
}).then((r) => r.json());
```

1. На какой адрес ушёл запрос, судя по Network?
2. Есть ли в Network `OPTIONS`? Почему?
3. Что пишет консоль сервера в колонке `Origin`?
4. Попробуй прежний вариант `fetch('http://localhost:3000/api/ping')` — что теперь?

**Часть В — скрипты**

Добавь в `package.json` корня Angular-проекта скрипт, который запускает сервер из корня (чтобы не переходить в папку `server`), и проверь, что `npm run server` работает.

## Критерии готовности

- [ ] `fetch('/api/ping')` с `localhost:4200` возвращает `{ pong: true }` без CORS в сервере
- [ ] Прокси подключён в `angular.json`, `ng serve` запускается без флагов
- [ ] Сервер запускается из корня проекта одной командой
- [ ] Ты можешь ответить: почему с прокси нет preflight-запросов?
- [ ] Ты можешь ответить: почему полный адрес `http://localhost:3000/...` снова упирается в CORS?
- [ ] Ты можешь ответить: будет ли прокси работать после `ng build`? Почему адрес `/api` всё равно останется верным?

## Типичные ловушки

- Изменили `angular.json`, но не перезапустили `ng serve`.
- Маршрут на сервере без префикса `/api` — прокси его не перешлёт.
- Относительный путь к файлам внутри сервера (появится в теме 6) ломается при запуске из корня — поэтому пути строят от `__dirname`.
