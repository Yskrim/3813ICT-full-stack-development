# 6.1 — Вход на сервере

**Тема:** соединяем Node и Angular (5_6)
**Место в теме:** первое из трёх, базовый концепт
**Время:** 50–60 минут
**Опирается на:** [3.2 — Прокси вместо CORS](../../03-hosting/02-proxy/README.md)
**Дальше:** [6.2 — Вход из Angular](../02-angular-login/README.md)

## Задача

Вход начинается на сервере: только сервер знает пароли и только он может сказать «да, это anna». В материале курса такой обработчик есть, и он рабочий — пока всё хорошо. Но стоит файлу с пользователями не прочитаться, как весь сервер падает; пароли пишутся в консоль; а если запустить сервер из другой папки, файл просто не находится.

Поэтому начнём с эксперимента: ты запустишь обработчик в стиле материала и своими руками сломаешь его тремя способами. А потом напишешь правильную версию и проверишь, что те же поломки она переживает спокойно.

## Зачем это задание

Код, который «работает, пока всё хорошо», — главный источник проблем на демонстрации. Здесь ты научишься писать серверный обработчик, который честно отвечает клиенту кодом ошибки и продолжает работать.

## Что проверяет

1. Ты понимаешь, почему `throw` в асинхронном колбэке роняет весь сервер.
2. Ты строишь пути к файлам от `__dirname`.
3. Ты отвечаешь правильными кодами: `400`, `401`, `500`.
4. Ты не отдаёшь пароль клиенту и не пишешь его в лог.

## Старт

Создай `server/data/users.json` (пароли открытым текстом — только для учебного проекта):

```json
[
  { "id": 1, "username": "super", "pwd": "123", "role": "superadmin", "birthdate": null, "age": null },
  { "id": 2, "username": "anna", "pwd": "123", "role": "groupadmin", "birthdate": "2001-05-14", "age": 25 },
  { "id": 3, "username": "ben", "pwd": "123", "role": "user", "birthdate": null, "age": null }
]
```

В материале курса поля называются `userid`, `userbirthdate`, `userage` — здесь они короче, суть та же. `id` совпадают с тестовыми пользователями из 1.3, поэтому сообщения из 4.3 будут принадлежать тем же людям.

Создай `server/routes/login-old.js` — обработчик в стиле материала, для экспериментов:

```js
var fs = require('fs');

module.exports = function (req, res) {
  var u = req.body.username;
  var p = req.body.pwd;
  c = u + p;
  console.log(c);
  fs.readFile('./data/users.json', 'utf8', function (err, data) {
    if (err) throw err;
    let users = JSON.parse(data);
    let i = users.findIndex((user) => user.username == u && user.pwd == p);
    if (i == -1) {
      res.send({ ok: false });
    } else {
      res.send({ ok: true });
    }
  });
};
```

И подключи его в `server.js` до `/api` 404:

```js
app.post('/api/login', require('./routes/login-old'));
```

Команды для проверки (из любого терминала):

```bash
# верный пароль
curl -X POST http://localhost:3000/api/login -H "Content-Type: application/json" -d '{"username":"anna","pwd":"123"}'
# неверный пароль
curl -X POST http://localhost:3000/api/login -H "Content-Type: application/json" -d '{"username":"anna","pwd":"000"}'
# нет пароля
curl -X POST http://localhost:3000/api/login -H "Content-Type: application/json" -d '{"username":"anna"}'
# после любого запроса — проверить, что сервер жив
curl http://localhost:3000/api/health
```

## Что сделать

**Часть А — сломать версию из материала**

Записывай в `observations.md`, что ответил curl и что случилось с сервером.

1. Запусти сервер из папки `server` (`npm run dev`) и проверь верный и неверный пароль. Что появилось в консоли сервера?
2. Останови и запусти сервер из **корня** проекта (`npm run server` из 3.2). Повтори вход. Что произошло и почему?
3. Верни запуск из `server`. Испорти `users.json` (удали последнюю `]`) и попробуй войти. Что стало с сервером? Отвечает ли `/api/health`?

Восстанови `users.json`.

**Часть Б — правильный обработчик**

Создай `server/routes/login.js` и подключи его вместо `login-old.js`. Требования:

1. Путь к `users.json` не зависит от того, откуда запущен сервер.
2. Нет имени или пароля — `400` с понятным сообщением, файл даже не читается.
3. Неверная пара — `401`.
4. Файл не прочитался или испорчен — `500`, **сервер продолжает работать**.
5. Успех — `200` и профиль пользователя **без пароля**.
6. В консоль сервера не попадает ни один пароль.
7. Сравнения строгие, переменные объявлены.

**Часть В — проверить на тех же поломках**

Повтори эксперименты части А с новым обработчиком, включая испорченный файл и запуск из корня.

## Критерии готовности

- [ ] В `observations.md` описано, как ломалась старая версия
- [ ] Новый обработчик отвечает `200` / `400` / `401` / `500` в нужных случаях
- [ ] С испорченным файлом `/api/health` продолжает отвечать
- [ ] Сервер работает при запуске и из `server`, и из корня
- [ ] Ни в ответе, ни в логе нет паролей
- [ ] Ты можешь ответить: почему `throw err` в колбэке `readFile` роняет весь процесс, а `try/catch` вокруг `await` — нет?
- [ ] Ты можешь ответить: от чего считается путь `'./data/users.json'` и от чего — `path.join(__dirname, ...)`?
- [ ] Ты можешь ответить: что даёт клиенту код `401` по сравнению с `200 { ok: false }`?

## Типичные ловушки

- `console.log(req.body)` «для отладки» — в логе окажется пароль.
- `try/catch` вокруг `fs.readFile` с колбэком — ошибка внутри колбэка его не заметит.
- Проверка пароля по `find` с `==` вместо `===`.
- Ответ всем объектом пользователя «потом уберу пароль».
