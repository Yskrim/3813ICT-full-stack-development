# 4.2 — Группы через HttpClient

**Тема:** HTTP-запросы (5_4)
**Место в теме:** второе из трёх, связка концептов
**Время:** 60–80 минут
**Опирается на:** [4.1 — Observable руками](../01-observables/README.md), [2.2 — Состояние каналов в сервисе](../../02-services/02-channel-state/README.md)
**Дальше:** [4.3 — Сообщения: страницы и перехватчик](../03-messages/README.md)

## Задача

В 2.2 каналы жили в памяти браузера: перезагрузил страницу — всё, что добавил, пропало. В настоящем чате данные хранит сервер, а клиент их запрашивает и меняет. Сделаем это для групп.

Устройство сервиса останется тем же, что в 2.2: состояние в сигнале, компоненты только показывают его и вызывают методы. Изменится источник данных: каждый метод теперь отправляет запрос, а сигнал обновляется только **после ответа сервера** — ведь только сервер знает, удалась ли операция и какой `id` получила новая группа.

Появятся и две вещи, которых в памяти не было: ожидание (пока запрос идёт, пользователь должен видеть, что что-то происходит) и отказ (сервер может ответить «нельзя» или вообще не ответить). Сервер в этом задании специально отвечает медленно и иногда отказывает, чтобы ты увидел оба случая.

## Зачем это задание

Это ровно тот код, из которого будет состоять Phase 2: сервисы групп, каналов и пользователей устроены одинаково. Сделав один правильно, остальные пишешь по образцу.

## Что проверяет

1. Ты пишешь сервис, методы которого возвращают Observable, а подписывается компонент.
2. Ты пользуешься `get`, `post`, `patch`, `delete` с типами ответов.
3. Ты обновляешь состояние из ответа сервера, не перезагружая весь список.
4. Ты показываешь пользователю загрузку и понятные сообщения об ошибках по кодам.

## Старт

Код сервера дан целиком — REST на Express был на неделе 3, а здесь тренируется клиент. Создай `server/routes/groups.js`:

```js
const express = require('express');
const router = express.Router();

let groups = [
  { id: 1, name: 'General' },
  { id: 2, name: 'Study Group' },
];
let nextId = 3;

// Задержка 800 мс — чтобы был виден индикатор загрузки
router.get('/', (req, res) => setTimeout(() => res.json(groups), 800));

router.post('/', (req, res) => {
  const name = (req.body?.name ?? '').trim();
  if (!name) return res.status(400).json({ error: 'Name is required' });
  const group = { id: nextId++, name };
  groups.push(group);
  res.status(201).json(group);
});

router.patch('/:id', (req, res) => {
  const group = groups.find((g) => g.id === Number(req.params.id));
  if (!group) return res.status(404).json({ error: 'Group not found' });
  const name = (req.body?.name ?? '').trim();
  if (!name) return res.status(400).json({ error: 'Name is required' });
  group.name = name;
  res.json(group);
});

router.delete('/:id', (req, res) => {
  const id = Number(req.params.id);
  if (id === 1) return res.status(403).json({ error: 'General cannot be deleted' }); // чтобы увидеть 403
  const before = groups.length;
  groups = groups.filter((g) => g.id !== id);
  if (groups.length === before) return res.status(404).json({ error: 'Group not found' });
  res.status(204).end();
});

module.exports = router;
```

В `server.js` подключи его **до** обработчика `/api` 404 и до статики:

```js
app.use('/api/groups', require('./routes/groups'));
```

В Angular:

```bash
ng g s services/group
ng g c pages/groups
```

Маршрут `/groups` (только для вошедших — `authGuard` из 2.3) и ссылка в навигации.

## Что сделать

**Часть А — `GroupService`**

1. Состояние: список групп в сигнале, наружу — только чтение.
2. `load()` — загрузить список; повторный вызов, пока список уже загружается или загружен, не отправляет второй запрос.
3. `create(name)`, `rename(id, name)`, `remove(id)` — возвращают Observable; после успешного ответа обновляют сигнал **ответом сервера**.
4. Адреса — относительные: `/api/groups`.

**Часть Б — страница групп**

1. Список групп; пока идёт загрузка — «Загрузка…», пустой список — «Групп нет».
2. Форма «новая группа».
3. У каждой группы кнопки «Переименовать» (новое имя спроси через `prompt`) и «Удалить».
4. Индикатор загрузки гаснет и при успехе, и при ошибке.

**Часть В — ошибки**

Покажи пользователю понятное сообщение для каждого случая и проверь все:

| Как вызвать | Ожидаемое сообщение |
|---|---|
| создать группу с пустым именем | имя обязательно (текст от сервера) |
| удалить General | удалять эту группу нельзя |
| переименовать группу, удалённую в соседней вкладке | группа не найдена |
| остановить сервер и нажать «Создать» | сервер недоступен |

## Критерии готовности

- [ ] После F5 группы, созданные раньше, на месте (они на сервере), пока сервер не перезапущен
- [ ] Созданная группа появляется в списке с `id` от сервера, без повторной загрузки всего списка
- [ ] Все четыре ошибки из таблицы показаны понятным текстом
- [ ] «Загрузка…» гаснет и при ошибке
- [ ] Сервис не подписывается сам на `create`/`rename`/`remove` — это делает компонент

- [ ] Ты можешь ответить: что лежит в `err.error` и чем оно отличается от `err.message`?

## Типичные ловушки

- Сигнал обновлён до ответа сервера — при ошибке интерфейс показывает то, чего на сервере нет.
- `subscribe` внутри сервиса — компонент не узнает ни о результате, ни об ошибке.
- После создания заново загружается весь список — лишний запрос.
- `id` новой группы придуман на клиенте.
