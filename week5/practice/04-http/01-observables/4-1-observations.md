**Часть Б — поток во времени**

1. Подпишись на `interval(500)` из RxJS и выводи значения. Через 2 секунды отпишись. Сколько значений успело прийти? Вызвался ли `complete`?
  - Сука ни слова про интервал не было в конспекте и в примерах, я не думал даже что такое есть.
  - Если вызывать без unsubscribe, будет идти бесконечно, пока не обновить страницу.
  - Если поставить setTimeout после подписки, то нужно вручную его отписать
    ```typescript
      partB1(): void {
        const interval$ = interval(500);

        const subscription = interval$.subscribe({
          next: (x) => console.log(x),
          error: (err) => console.log(err),
          complete: () => console.log('stream complete')
        })

        setTimeout(() => {
          subscription.unsubscribe();
        }, 2000);
      }
    ```
  - Дальше когда искал на него инфу наткнулся на pipe(take(n)) который берет N значений из интервала и потом пайп его отписывает сам. Тут все равно создаем поток и все равно пишем обзервер (можно без ошибки, в этом примере ее не может быть)
    ```typescript
      partB1_1(): void {
        const sub$ = interval(500).pipe(take(4));
        sub$.subscribe({
          next: (value) => console.log(value),
          complete: () => console.log('stream complete')
        })
      }
    ```

2. Добавь `finalize` и сравни: какой из обработчиков годится для «выключить индикатор загрузки» — `complete` или `finalize`? Почему?
  - Finalize это метод пайпа, чтобы завершить стрим в любом случае. Пайп пишется сразу на стриме когда он создается и finalize вызывается, когда отработал сам обзервер и в пайпе очередь дошла до него.
