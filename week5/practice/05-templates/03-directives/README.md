# 5.3 — Свои директивы

**Тема:** шаблоны и директивы (5_5)
**Место в теме:** третье из трёх, рабочий кусок Phase 2
**Время:** 60–80 минут
**Опирается на:** [5.2 — Лента сообщений](../02-message-feed/README.md), [4.2 — Группы через HttpClient](../../04-http/02-group-crud/README.md)
**Дальше:** [6.1 — Вход на сервере](../../06-login/01-login-route/README.md)

## Задача

В 4.2 группы переименовываются через `prompt`, а удаляются одним нажатием без всякого подтверждения. Для учебного задания сойдёт, для чата — нет: `prompt` выглядит чужеродно, а случайное удаление группы вместе со всеми каналами — неприятный сюрприз.

Сделаем по-человечески. Переименование — прямо в строке списка: нажал «Переименовать», на месте имени появилось поле с курсором внутри, Enter сохраняет, Escape отменяет. Удаление — с вопросом «Точно удалить?».

Обе вещи понадобятся не в одном месте: поле с автофокусом — везде, где что-то редактируется «по кнопке», подтверждение — у каждой опасной кнопки. Поэтому их поведение выносится в **атрибутные директивы**: `appAutofocus` ставит курсор в поле, `appConfirmClick` спрашивает подтверждение и только потом сообщает о клике. А значение из поля ты возьмёшь шаблонной переменной — без отдельного поля в классе под каждую строку.

## Зачем это задание

Свои директивы — способ не копировать одно и то же поведение по компонентам. А шаблонные переменные внутри `@for` — частый приём для «редактирования на месте», и здесь хорошо видно их правило области видимости.

## Что проверяет

1. Ты пишешь атрибутную директиву, которая работает с элементом через `ElementRef`.
2. Ты слушаешь события элемента через `host` и передаёшь наружу событие директивы.
3. Ты используешь шаблонную переменную внутри `@for` и понимаешь её область видимости.
4. Ты подключаешь директивы через `imports` и знаешь, что бывает, если забыть.

## Старт

```bash
ng g d directives/autofocus
ng g d directives/confirm-click
```

## Новое в этом задании: событие директивы

Директива может не только менять элемент, но и сообщать о событиях — так же, как компонент. Событие объявляется через `@Output()` с `EventEmitter` или функцией `output()`:

```ts
readonly done = output<void>();   // в шаблоне: <button appSomething (done)="...">
// где-то в коде директивы:
this.done.emit();
```

## Что сделать

**Часть А — `appAutofocus`**

Когда элемент с этим атрибутом появляется на странице, в него ставится курсор. Подумай, в каком хуке жизненного цикла это делать.

**Часть Б — `appConfirmClick`**

1. Атрибут принимает текст вопроса: `appConfirmClick="Удалить группу?"`. Если текст не указан — «Вы уверены?».
2. По клику на элемент показывается `confirm` с этим текстом.
3. Если пользователь согласился — директива генерирует событие `confirmed`. Если нет — ничего не происходит.

**Часть В — редактирование на месте**

На странице групп из 4.2:

1. Вместо `prompt` — режим редактирования строки: имя заменяется полем ввода с текущим именем (с `appAutofocus`), кнопками «Сохранить» и «Отмена».
2. Одновременно редактируется только одна строка.
3. Значение поля бери **шаблонной переменной** на `<input>`, без отдельного поля в классе.
4. Enter сохраняет, Escape отменяет.
5. Кнопка «Удалить» работает через `appConfirmClick` и событие `confirmed`.

**Часть Г — эксперимент**

1. Убери `ConfirmClickDirective` из `imports` страницы групп. Что происходит при клике? Есть ли ошибка?
2. Попробуй обратиться к шаблонной переменной поля **снаружи** `@for` (например, в кнопке под списком). Что говорит компилятор?

Верни всё на место.

## Критерии готовности

- [ ] Курсор сам оказывается в поле при входе в редактирование
- [ ] Enter и «Сохранить» переименовывают через `GroupService`, Escape и «Отмена» — отменяют
- [ ] Удаление спрашивает подтверждение; при отказе запрос не уходит
- [ ] В классе страницы нет поля под новое имя группы
- [ ] Обе директивы можно поставить на любой другой элемент без изменений
- [ ] Ты можешь ответить: почему фокус ставят не в конструкторе директивы?
- [ ] Ты можешь ответить: что случилось, когда директива пропала из `imports`, и почему не было ошибки?
- [ ] Ты можешь ответить: почему у каждой строки своя шаблонная переменная с одним и тем же именем?

## Типичные ловушки

- `appConfirmClick` и обычный `(click)` на одной кнопке — удаление сработает и без подтверждения.
- Фокус в конструкторе — элемента ещё нет в DOM.
- Пустая строка из атрибута без текста принимается за вопрос — `confirm('')`.
- Директива не добавлена в `imports` — атрибут молча игнорируется.
