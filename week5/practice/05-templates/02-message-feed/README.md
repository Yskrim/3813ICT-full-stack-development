# 5.2 — Лента сообщений

**Тема:** шаблоны и директивы (5_5)
**Место в теме:** второе из трёх, связка концептов
**Время:** 50–70 минут
**Опирается на:** [5.1 — Разминка control flow](../01-control-flow/README.md), [4.3 — Сообщения: страницы и перехватчик](../../04-http/03-messages/README.md)
**Дальше:** [5.3 — Свои директивы](../03-directives/README.md)

## Задача

В 4.3 сообщения приходят с сервера порциями, но выглядят как список строк «автор: текст». Пора сделать из этого ленту чата. У настоящей ленты есть привычные правила: свои сообщения справа, чужие слева; системные («anna присоединилась») — по центру и серым; картинки показываются картинками; если один человек написал несколько сообщений подряд, его имя пишется только над первым; у каждого сообщения — время.

Всё это — работа шаблона. Логику загрузки ты уже написал в 4.3 и трогать её не будешь: ты вынесешь отображение в отдельный компонент, который получает сообщения и `id` текущего пользователя и только рисует. Такой компонент легко проверять и легко переиспользовать.

## Зачем это задание

Лента — самый насыщенный шаблон чата: в нём одновременно цикл, выбор по типу, условия, привязки классов и форматирование. Если он получится аккуратным, остальные шаблоны Phase 2 будут проще.

## Что проверяет

1. Ты комбинируешь `@for`, `@switch` и `@if` в одном шаблоне.
2. Ты пользуешься `$index`, чтобы сравнить элемент с предыдущим.
3. Ты привязываешь классы по условию.
4. Ты разделяешь компонент «загружает данные» и компонент «показывает данные».

## Старт

Добавь серверу картинки: в `server/routes/messages.js` в генерации тестовых сообщений сделай каждое седьмое сообщением-картинкой:

```js
// внутри Array.from(..., (_, i) => { ... }) перед return:
const isImage = i % 7 === 3;
// в возвращаемом объекте:
//   type: i % 10 === 0 ? 'system' : isImage ? 'image' : 'text',
//   imageUrl: isImage ? `https://picsum.photos/seed/chat${i}/240/160` : undefined,
```

В модели `Message` на клиенте добавь тип `'image'` и необязательное поле `imageUrl`.

```bash
ng g c components/message-list
```

## Новое в этом задании

**Входные параметры-сигналы.** Кроме декоратора `@Input()`, в новых версиях Angular входной параметр объявляют функцией `input()` — он становится сигналом:

```ts
readonly title = input.required<string>();   // обязательный; читается как title()
readonly color = input('grey');              // необязательный, со значением по умолчанию
```

Можно использовать любой вариант.

**Пайп `date`** форматирует дату в шаблоне: `{{ m.sentAt | date: 'HH:mm' }}` → `14:05`. Для этого в `imports` компонента нужен `DatePipe` из `@angular/common`.

## Что сделать

**Часть А — компонент ленты**

`MessageListComponent` получает два входных параметра — массив сообщений и `id` текущего пользователя — и ничего не загружает сам.

**Часть Б — правила отображения**

1. Системные сообщения — по центру, серым курсивом, без автора и времени.
2. Картинки — `<img>` с разумным `alt`.
3. Текст — обычный абзац.
4. Свои сообщения прижаты вправо и другого цвета.
5. Имя автора показывается только если предыдущее сообщение написал кто-то другой (или это первое сообщение).
6. У каждого не системного сообщения — время в формате `HH:mm`.
7. Пустой канал — «В канале пока нет сообщений».

**Часть В — подключение**

Замени простой список в `ChannelMessagesComponent` из 4.3 на `<app-message-list>`. Кнопка «Загрузить более старые» и форма отправки остаются в `ChannelMessagesComponent`.

**Часть Г — проверка**

1. Подгрузи старые сообщения — группировка по авторам не ломается на стыке порций.
2. Войди как anna, потом как ben — «свои» меняются местами.
3. Открой пустой канал.

## Критерии готовности

- [ ] Все правила из части Б выполняются
- [ ] `MessageListComponent` не внедряет ни одного сервиса — только входные параметры
- [ ] В шаблоне нет старых структурных директив
- [ ] Ты можешь ответить: как ты определил, показывать ли имя автора? Что происходит с первым сообщением?
- [ ] Ты можешь ответить: почему при подгрузке старых сообщений Angular не перерисовывает уже показанные? Что за это отвечает?
- [ ] Ты можешь ответить: зачем разделять компонент, который загружает, и компонент, который показывает?

## Типичные ловушки

- `track $index` для ленты, в начало которой добавляются элементы: Angular пересоздаст все строки.
- Сравнение с предыдущим сообщением без проверки на первый элемент — обращение к `undefined`.
- Логика загрузки, перенесённая в компонент ленты.
- `DatePipe` не добавлен в `imports` — ошибка компиляции шаблона.
