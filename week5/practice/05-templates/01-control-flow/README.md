# 5.1 — Разминка control flow

**Тема:** шаблоны и директивы (5_5)
**Место в теме:** первое из трёх, базовый концепт
**Время:** 40–50 минут
**Опирается на:** [00 — Подготовка проекта](../../00-setup/README.md) (можно делать в любой момент)
**Дальше:** [5.2 — Лента сообщений](../02-message-feed/README.md)

## Задача

В шаблонах Angular сейчас два синтаксиса: новый, с блоками `@if`, `@for`, `@switch`, и старый, со звёздочками `*ngIf`, `*ngFor`. Писать ты будешь на новом, а читать придётся оба: старый живёт в материалах курса и в чужом коде.

Здесь ты на маленьком списке пользователей потренируешь все блоки нового синтаксиса и их тонкости — обязательный `track`, `@empty`, встроенные переменные `$index` и `$last`, `@let`. Потом переведёшь старый шаблон на новый и проверишь две вещи о привязках, на которых часто спотыкаются.

## Зачем это задание

В ленте сообщений (5.2) и списках Phase 2 все эти блоки встретятся одновременно. Если синтаксис уже в пальцах, там можно думать о логике, а не о скобках.

## Что проверяет

1. Ты пишешь `@if` / `@else if` / `@else`, `@for` с `track` и `@empty`, `@switch` / `@case` / `@default`.
2. Ты пользуешься переменными `$index`, `$first`, `$last`, `$odd`.
3. Ты переводишь `*ngIf`, `*ngFor`, `ngSwitch` в новый синтаксис.
4. Ты понимаешь разницу между привязкой свойства и интерполяцией и из чего состоит `[(ngModel)]`.

## Старт

Работай на странице `playground`. Добавь в класс данные:

```ts
protected users = signal([
  { id: 1, username: 'super', role: 'superadmin', status: 'online' },
  { id: 2, username: 'anna', role: 'groupadmin', status: 'away' },
  { id: 3, username: 'ben', role: 'user', status: 'offline' },
  { id: 4, username: 'chen', role: 'user', status: 'online' },
]);
```

Для части Е нужен `FormsModule` в `imports` компонента площадки.

## Что сделать

**Часть А — список**

1. Выведи пользователей через `@for` с правильным `track`.
2. Перед именем — номер, начиная с 1.
3. Первый в списке помечен «(первый)», последний — «(последний)».
4. Чётные и нечётные строки разного цвета — через привязку класса.
5. Кнопка «Очистить / вернуть» опустошает и восстанавливает список; для пустого показывается «Пользователей нет».

**Часть Б — роль**

Рядом с именем — подпись по роли: `superadmin` → «администратор системы», `groupadmin` → «администратор групп», остальные → «участник». Используй `@if` / `@else if` / `@else`.

**Часть В — статус**

Перед именем — цветная точка по статусу: `online` — зелёная, `away` — жёлтая, всё остальное — серая. Используй `@switch`.

**Часть Г — `@let`**

Над списком выведи «В сети: N из M», объявив нужные значения через `@let`.

**Часть Д — перевод старого шаблона**

Перепиши этот шаблон на новый синтаксис (результат вставь в `observations.md`):

```html
<ul *ngIf="users().length; else empty">
  <li *ngFor="let u of users(); let i = index; trackBy: trackById">
    {{ i + 1 }}. {{ u.username }}
    <ng-container [ngSwitch]="u.status">
      <b *ngSwitchCase="'online'">в сети</b>
      <i *ngSwitchCase="'away'">отошёл</i>
      <span *ngSwitchDefault>не в сети</span>
    </ng-container>
  </li>
</ul>
<ng-template #empty><p>Пусто</p></ng-template>
```

**Часть Е — привязки**

1. Добавь две кнопки: `<button [disabled]="false">A</button>` и `<button disabled="{{ false }}">B</button>`. Какая активна? Почему?
2. Добавь поле поиска, которое фильтрует список по имени. Свяжи его **без** `[(ngModel)]` — двумя отдельными привязками, в которые он разворачивается.

## Критерии готовности

- [ ] Все части работают на площадке
- [ ] Ни одной старой структурной директивы в итоговом шаблоне площадки
- [ ] Перевод из части Д сохраняет поведение: номера, статусы, пустой список
- [ ] Ты можешь ответить: зачем `track` и что написать, если у элементов нет `id`?
- [ ] Ты можешь ответить: почему кнопка B заблокирована?
- [ ] Ты можешь ответить: во что разворачивается `[(ngModel)]`?

## Наводящие вопросы (если застрял)

- Как `@for` сообщает, что элемент последний? Как — что строка нечётная?
- Где должен стоять `@empty` относительно `@for`?
- Во что превращается `let i = index` из `*ngFor` в новом синтаксисе?
- Какое событие генерирует `ngModel`, когда меняется значение поля?

## Типичные ловушки

- `@If` или `@elseif` — блоки пишутся строчными, а «иначе если» — двумя словами.
- `@for` без `track` — ошибка компиляции.
- Строки в `@case` без кавычек: `@case (online)` ищет переменную `online`.
- Фильтр списка, который меняет исходный массив вместо вычисления нового.
