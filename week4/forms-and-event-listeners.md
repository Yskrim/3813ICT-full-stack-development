# Forms and Event Handling

В ангуларе формы используют `ngModel` аттрибут, чтобы определить, какой компонент формы будет передавать и получать значение.

`ngModel` -- директива ангулар, связывает поле формы со свойством (property) в компоненте.

## Зачем она нужна?

Держит в синхроне

- (view), то что пользователь видит/вводит в инпут
- (Model), свойство класса компонента

Позволяет выполнить two-way binding `[(ngModel)]` - банан в коробке

```html
<input [(ngModel)]="username" />
<!-- то же самое что -->
<input [ngModel]="username" (ngModelChange)="username = $event" />
```

`[ngModel]` - значение компонента идет в поле
`(ngModelChange)` - новое значение из поля идет обратно в компонент

Пример

```ts
// chat.ts
import { Component, signal } from "@angular/core";
import { FormsModule } from "@angular/forms"; // импортируем функционал

@Component({
	imports: [FormsModule], // передаем функционал в компонент
	selector: "app-root",
	styleUrl: "./app.css",
	templateUrl: "./app.html",
})
export class App {
	protected readonly title = signal("ngModel");

	// свойство модели — живёт ВНУТРИ класса компонента
	username = ""; // нужно начальное значение, иначе не будет работать
}
```

```html
<!-- chat.component.html -->
<input [(ngModel)]="username" />
<!-- two-way binding изза [()] -->
<p>Hello, {{ username }}</p>
```

В инпут печатается новое значение и модель сразу передает его в интерполированное поле `{{ username }}`

Обязательно нужно импортировать `FormsModule` в тс файл, чтобы получить функционал модели
В реактивных формах используют `formControl` или `formControlName` вместо `[(ngModel)]`

## Что собой представляет `ngModel`

`ngModel` - это объект (экземпляр директивы), но не «магический subscribe прямо на DOM-поле» в том виде, как в RxJS.

Когда пишу [(ngModel)]="username", Angular создаёт экземпляр класса NgModel.

```
[компонент]             [директива NgModel]         [DOM input]
username  <---------->  FormControl  <------------> ControlValueAccessor
                        (модель формы)              (мост к <input>)
```

- NgModel — директива-менеджер
- FormControl — внутренний объект состояния (value, valid, touched, dirty…)
- ControlValueAccessor — адаптер к реальному элементу (<input>, <select>…)

В ней нет `subscribe`, ангулар добавляет обычный слушатель через ControlValueAccessor, а не подписывается на изменения вручную.

В `FormControl` есть `subscribe` внутри `observable`. Он управляет одним полем, всю форму описывает `FormGroup`

ngModel удобнее для простых форм, reactive (FormControl / FormGroup) — когда нужна явная логика и контроль.
Form Control - представляет форму как обьект тс, - подписывается и реагирует на изменения (для сложной логики), - может динамически добавлять/убирать поля, - проще тестируется, - более предсказуемый поток данных, один источник правды - модель формы в классе, (в ngModel - шаблон + свойства)

## Event handling

Вместо прямой связи инпута с моделью, можно обработать событие с кнопки, чтобы получить доступ к значению.

Например, если форма отправляется на сервер, лучше обработать одну форму, когда действительно нужно, чем отправлять ее на каждое изменение каждого значения.

Получить значение инпута можно двумя способами:

1. Можно добавить обработчик клика на кнопку и получить значение в обработчике,
2. Либо создать форму и получать значение на ее отправку.

Обработка событий - это термин для взаимодействия с пользователем. Любое его действие на странице - событие (event).

Ивенты включают в себя вообще любое действие пользователя: клики, движение мышки, тап на экране, жест, даже данные передаваемые по сети.

Используя роуты, можно менять страницы исходя из роута, принадлежащего конкретному компоненту (вроде кнопки или ссылки)

А если нужно выполнить логику? Например, нужно провалидировать пароль перед переходом к аккаунту?
Обработчики в компонентах могут выполнять свой код перед действиями.

Обработка ивентов собирает 3 вещи:

1. Источник ивента (кнопка)
2. Действие ивента (клик)
3. Обработчик ивента (логика)

Ивенты - простые HTML/JavaScript события
Мы связываем источник, действие и обработчик внутри компонента в HTML шаблоне.

Пример: `<button (click)=”itemClicked()”> submit <\button>`
Действие (click) связывается с источником (button) и выполняет обработчик (itemClicked()), который описывается в тс файле компонента

В примере проекта, есть обработчик события для формы, когда она отправляется, он выполняет свою логику: выводит сообщение на странице и дублирует его в консоль. Так же свой обработчик есть для кнопки, он считает количество кликов по ней.

До этого говорилось о том, как ангулар подвязывает значения (data binding) чтобы показать данные в шаблоне.
Ивенты часто приводят к изменениям на странице.
Чтобы поменять данные на странице, нужно:

1. Создать свойство в компоненте (в классе) и хранить его значение
2. Выводить его в шаблоне используя data binding
3. Менять свойтво компонента, когда случается ивент

## this.

В обработчике события (метод класса) мы обращаемся к полям компонента через this — так TypeScript понимает, что речь о свойстве этого экземпляра класса, а не о локальной переменной.

```ts
export class App {
	email = "";
	loginMessage = "";
	onLogin() {
		// ❌ TypeScript ищет локальную переменную email / loginMessage
		//    внутри функции их нет.
        // можно было бы передавать их как параметры, но не вижу смысла, если есть this и при каждом использовании нужно было бы писать имена переменных в параметы, это просто лишнее.
		loginMessage = `Отправлено: ${email}`;
	}
}
```

```ts
export class App {
  email = '';
  loginMessage = '';
    onLogin() {
        // ✅ this = текущий экземпляр компонента App
        this.loginMessage = `Отправлено: ${this.email}`;
    }
}
```
