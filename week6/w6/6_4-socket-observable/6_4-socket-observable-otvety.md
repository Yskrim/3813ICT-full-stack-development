## Понимание

1. `socket.on('new-message', callback)` регистрирует функцию, которую библиотека вызовет при событии с таким именем.
2. Сервис централизует подключение и протокол событий, а компонент оставляет работу с представлением. Это облегчает повторное использование и тестирование.
3. Она выполняется при подписке и обычно настраивает источник. В нашем примере она добавляет обработчик сокет-события.
4. Teardown — функция очистки, возвращаемая логикой Observable. RxJS вызывает её при отписке; здесь она снимает socket listener.
5. Такие события обычно продолжаются, пока соединение активно. Без отписки обработчик может оставаться после уничтожения компонента и обновлять уже неиспользуемое состояние.

## Анализ кода

6. Callback получит три вызова `next`, по одному на каждое событие.
7. `map` убирает пробелы по краям каждой строки, а `filter` оставляет только строки с длиной больше нуля.
8. API снимает обработчик по ссылке на функцию. Другая функция, даже с тем же телом, имеет другой объектный identity и не удалит исходную.
9. Каждая подписка добавит свой listener; одно входящее событие вызовет оба. Если нужен один общий listener, потребуется подход с разделяемой подпиской.
10. Нет. Teardown снимает listener, созданный конкретной Observable-подпиской. Общее соединение может продолжать обслуживать приложение или другие компоненты.

## Связь с предыдущими темами

11. Promise обычно представляет один итоговый результат или ошибку. Поток сокет-сообщений может выдавать много событий на протяжении соединения.
12. И сокет-событие, и Observable связаны с идеей «событие произошло — обработчик отреагировал». Но сокет — API сетевой библиотеки и источник данных из другой программы, а Observable — модель RxJS для представления последовательности уведомлений.
13. В современных примерах операторы импортируют и передают в `pipe()`. Прямой `observable.map()` относится к старой версии RxJS и текущему API не соответствует.
14. Операторы собирают обработку как последовательные шаги и оставляют исходный Observable неизменённым. Компонент подписывается уже на поток с нужным представлением данных.

## Объясни ученику

15. Сервис подписывает обработчик на событие, например `new-message`. Когда оно приходит, callback передаёт данные в `observer.next`. RxJS передаёт значение операторной цепочке и активному подписчику; обработчик компонента добавляет сообщение в `this.messages`, после чего шаблон Angular отображает обновлённый массив.
