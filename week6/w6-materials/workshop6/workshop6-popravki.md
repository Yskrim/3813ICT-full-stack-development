## П-2. Страница 1 — npm зависимости

Для клиента нужен `socket.io-client`, на сервере — `socket.io`. В документе пункты установки это в целом указывают, хотя вводный список клиента сокращённо пишет `socket.io`. Следуй конкретной роли пакета, а не общему названию библиотеки.

## П-3. Страница 2 — Angular-модули и формы

`FormsModule` нужен для `[(ngModel)]`. Импорт `CommonModule` относится к NgModule-проекту и нужен, в частности, для `*ngFor`; современные standalone-проекты могут подключать нужные API иначе или применять `@for`. Сначала определи тип Angular-проекта.

**Источник:** [Angular Forms](https://angular.dev/guide/forms)

## П-4. Страница 2 — CORS Socket.IO

В workshop-подсказке Socket.IO версии 4.2 CORS задаётся во втором аргументе создания `Server`, с точным origin `http://localhost:4200`. В версиях 3+ CORS нужно настраивать явно. Для текущей конфигурации проверь официальную документацию установленной версии. CORS не является механизмом авторизации.

**Источник:** [Socket.IO: Handling CORS](https://socket.io/docs/v4/handling-cors/)

<a id="p-5"></a>

## П-5. Страницы 1–2 — создание HTTP server

Слайды подразумевают связывание Express с Socket.IO и отдельный запуск прослушивания порта. В современном Node.js явная форма обычно выглядит так:

```js
const httpServer = createServer(app);
const io = new Server(httpServer, options);
httpServer.listen(3000);
```

Важно, чтобы Socket.IO был создан на том HTTP server, который начинает слушать порт. Сверяй импорты/синтаксис с версией Node.js и Socket.IO.

**Источник:** [Socket.IO server initialization](https://socket.io/docs/v4/server-initialization/)

## П-6. Страница 3 — рассылка отправителю

Если сервер рассылает через `io.emit`, событие получает и отправитель. Это может дублировать локальное добавление сообщения в клиенте. Используй `socket.broadcast.emit` для остальных подключённых клиентов или обнови клиентскую логику, чтобы показывать серверную копию ровно один раз.
