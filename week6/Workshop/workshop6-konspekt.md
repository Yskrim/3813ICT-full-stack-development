## Цель работы

В предыдущих темах мы уже разобрали сетевую связь и поток событий. Теперь соберём их в приложение: Node.js-сервер на порту `3000`, Angular-клиент на `4200`, Socket.IO-событие для отправки текста и список сообщений в интерфейсе.

Workshop оценивается в 2.5%; по условию исходного файла завершённую работу нужно показать преподавателю в лаборатории. Этот пакет помогает пройти задания и подготовить демонстрацию, но не заменяет требования вашего преподавателя к сдаче. ⚠ [П-1](workshop6-popravki.md#p-1)

## Архитектура проекта

```text
chat/
├── src/                    Angular-клиент
└── server/                 Node.js-сервер
    ├── server.js           создание HTTP/Socket.IO сервера
    ├── sockets.js          обработчики событий
    └── listen.js           запуск прослушивания порта
```

Два приложения запускаются отдельно. Angular показывает интерфейс, а Node.js-сервер принимает соединение и пересылает события между клиентами. Это та же схема, что мы разобрали в [6.5](../materials/6_5-sockets-coding-konspekt.md#s1).

## Задание 1. Создать клиент и сервер

Создай Angular-проект `chat`. Для клиента установи `bootstrap` и `socket.io-client`. В отдельной папке `server` инициализируй npm-проект и установи `express`, `socket.io`, `cors` только если выбранная конфигурация действительно использует эти зависимости. Пакет `socket.io` работает на сервере, `socket.io-client` — в браузере. ⚠ [П-2](workshop6-popravki.md#p-2)

Разделение server code на три файла помогает держать входную точку, сокет-обработчики и запуск сервера отдельно. Можно реализовать их иначе, если преподаватель не требует именно эту структуру.

## Задание 2. Добавить интерфейс чата

Создай компонент чата с текстовым полем, кнопкой отправки и списком полученных сообщений. Добавь маршрут, чтобы он отображался в `router-outlet`. При нажатии кнопки компонент вызывает метод сервиса; сетевую логику не нужно копировать в шаблон.

В старом NgModule-проекте `[(ngModel)]` требует `FormsModule`, а для `*ngFor` обычно нужен `CommonModule` в соответствующем модуле. В standalone-проекте зависимости подключаются на уровне компонента. ⚠ [П-3](workshop6-popravki.md#p-3)

## Задание 3. Реализовать сокет-события

Сервер принимает соединение и слушает событие `message`; клиент отправляет текст через `emit`, а сервер публикует новое событие подключённым клиентам. Имена событий на обеих сторонах должны совпадать.

```text
Angular service --emit("message")--> Socket.IO server
Angular component <--Observable/listener-- server event
```

Как мы уже знаем из [6.4](../materials/6_4-socket-observable-konspekt.md#s3), сервис может предоставить входящие сообщения как Observable. Не забудь teardown listener и отписку компонента при его уничтожении.

## Запуск и демонстрация

Запусти Node-сервер на `localhost:3000` и Angular dev server на `localhost:4200`. Открой два окна/вкладки браузера. Отправь сообщение в одном клиенте и убедись, что другие подключённые клиенты его получают.

Если браузер блокирует запрос между портами, настрой CORS для нужного origin в опциях Socket.IO server. Разрешай локальный origin, используемый клиентом. CORS не заменяет аутентификацию или проверки доступа. ⚠ [П-4](workshop6-popravki.md#p-4)

## Подготовка к показу

- Сервер запускается и принимает соединения.
- Открыты два клиента.
- Сообщение отправляется из одного клиента и отображается у остальных согласно выбранной логике рассылки.
- Понимаешь разницу между событием Socket.IO и Observable-обёрткой.
- Можешь объяснить, где сервер принимает событие и где UI добавляет сообщение.
