# 04 — Socket.IO сервер

Конспекты: `6-3-Sockets.md`, `6-5-Sockets-coding-example.md`.

Зачем это на практике: это скелет серверной части ассайнмента. Здесь же руками проверяются две вещи, которые в лекциях сформулированы неточно: кто получает сообщение при разных способах рассылки и почему без CORS ничего не соединяется.

Клиент один на все задания — `public/index.html`. Он подключается к `http://localhost:3000`, печатает любое пришедшее событие и умеет по галочке добавлять твоё сообщение локально. Менять его почти не придётся.

Серверные файлы здесь на CommonJS (`require`), как в лекции и в ассайнменте — за это отвечает локальный `package.json` с `"type": "commonjs"`.

## Задание 1 — эхо-сервер

Файл: `task-1-echo.js`, запуск: `npm run sockets:1`, затем открой `http://localhost:3000`.

Что сделать:

- собрать express-приложение, отдать статику из `public/`;
- создать http-сервер через `createServer(app)` и повесить на него socket.io;
- на событие `connection` печатать в консоль `socket.id`;
- на событие `message` от клиента отвечать **только этому же клиенту** событием `echo`;
- на `disconnect` печатать в консоль, кто ушёл и по какой причине.

**Критерии**

- Открыты два окна браузера: сообщение, отправленное из первого, возвращается **только в первое**. Второе окно не видит ничего.
- В консоли сервера видны подключения с разными `socket.id` и отключения при закрытии вкладки.
- Ты можешь объяснить, почему socket.io навешивается на результат `createServer(app)`, а не на `app`.
- Перезагрузка страницы даёт новый `socket.id` — проверь и запомни этот факт.

**Ожидаемое поведение в консоли сервера**

```
сервер слушает http://localhost:3000
клиент подключился: kX9d...
клиент ушёл: kX9d... transport close
```

## Задание 2 — чат и выбор способа рассылки

Файл: `task-2-chat.js`, запуск: `npm run sockets:2`.

Что сделать:

- принимать `message` и рассылать его как `new-message` в формате `{ author, text }`, где `author` — первые 4 символа `socket.id`;
- сначала реализовать рассылку через `io.emit` и проверить работу в двух окнах **с включённой** галочкой «добавлять локально»;
- затем переключить на `socket.broadcast.emit` и проверить снова;
- оставить в коде тот вариант, который правильно работает с этим клиентом, а второй закомментировать с пояснением.

**Критерии**

- Ты своими глазами увидел дубль своего сообщения в варианте `io.emit` + локальное добавление.
- Ты увидел обратную ситуацию: `socket.broadcast.emit` без галочки — автор своего сообщения не видит вообще.
- В комментарии в коде записано, какой вариант когда нужен (это ровно та ошибка, что была в слайде 6.5).
- Сообщения от разных окон различимы по `author`.

## Задание 3 — модульный сервер и CORS

Папка: `task-3/`, запуск сервера: `npm run sockets:3`, запуск клиента: `npm run sockets:3-client` (во втором терминале), открывать `http://localhost:4200`.

Теперь страница отдаётся с **другого порта**, то есть с другого origin — как настоящий Angular на 4200 против Node на 3000.

Что сделать:

- разложить сервер по трём файлам: `server.js` (сборка), `socket.js` (вся логика событий), `listen.js` (запуск);
- **сначала запустить без опции `cors`** и посмотреть, что скажет консоль браузера;
- затем добавить `cors: { origin: 'http://localhost:4200' }` в `new Server(...)` и убедиться, что соединение встало;
- оставить в `server.js` комментарий, чем `app.use(cors())` отличается от опции `cors` у socket.io.

**Критерии**

- Ты видел ошибку CORS в консоли браузера своими глазами и понимаешь, почему `app.use(cors())` её не лечит.
- После настройки чат работает между двумя окнами на `localhost:4200`.
- Логика событий целиком в `socket.js`, в `server.js` её нет.
- `socket.js` экспортирует функцию, принимающую `io`, и не создаёт сервер сам.
- Если убрать `cors` обратно — снова падает. Проверь, чтобы не осталось сомнений, что дело именно в нём.
