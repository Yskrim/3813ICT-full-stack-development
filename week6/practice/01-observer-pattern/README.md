# 01 — Паттерн Observer своими руками

Конспекты: `6-0-ReactiveProgramming.md`, `6-1-observables.md`.

Зачем это на практике: прежде чем пользоваться RxJS, надо понимать, что внутри него нет магии — есть массив наблюдателей и цикл вызовов. После этой темы код Angular-сервисов перестаёт быть «чёрным ящиком», а баги с потерянными и продублированными сообщениями становятся предсказуемыми.

Запуск: `node 01-observer-pattern/task-1-subject.ts`

---

## Задание 1 — типизированный Subject с отпиской

Файл: `task-1-subject.ts`

Реализуй `Subject<T>`, который умеет раздавать значения наблюдателям и позволяет отписаться. Это основа всего остального: и `Subject` из RxJS, и сервис в Angular работают ровно так.

Что сделать:

- хранить список наблюдателей внутри класса (наружу его не отдавать);
- `subscribe(observer)` возвращает объект с методом `unsubscribe()`, который убирает **именно этого** наблюдателя, не задев остальных;
- `next(value)` рассылает значение всем текущим наблюдателям.

**Критерии**

- Значение, отправленное до подписки, не приходит никому: у обычного Subject нет памяти.
- После `unsubscribe()` конкретный наблюдатель больше ничего не получает, а остальные продолжают получать.
- Типизация работает: `chat.next('просто строка')` подсвечивается редактором как ошибка, потому что поток объявлен как `Subject<Message>`.
- Список наблюдателей приватный — снаружи в него нельзя дописать наблюдателя напрямую.

**Ожидаемый вывод**

```
счётчик: +1
счётчик: +1
в списке: [ 'привет', 'как дела' ]
```

Обрати внимание: `счётчик` срабатывает два раза, а в списке два сообщения из четырёх отправленных. Пока не поймёшь, почему именно эти два, — дальше не иди.

## Задание 2 — разные реализации одного интерфейса

Файл: `task-2-observers.ts`

`Subject` здесь уже готов — это инструмент. Твоя задача написать три разных наблюдателя за одним и тем же потоком сообщений, как это будет в чате: список сообщений на экране, счётчик непрочитанных в сайдбаре, лог для отладки.

Что сделать:

- `MessageListObserver` — складывает сообщения в свой массив;
- `UnreadCounterObserver` — считает только **чужие** сообщения (автор не равен текущему пользователю);
- `LoggerObserver` — печатает сообщения в консоль в своём формате.

**Критерии**

- Все три класса объявлены как `implements Observer<Message>` и компилируются без ошибок.
- Чтобы добавить четвёртого наблюдателя, править `Subject` не нужно **вообще** — это и есть low coupling из конспекта 6.0.
- Счётчик непрочитанных не увеличивается на своих собственных сообщениях.
- Порядок вызова наблюдателей соответствует порядку подписки.

**Ожидаемый вывод**

```
[log] anton: привет
[log] bob: как дела
[log] bob: ты тут?
сообщений в списке: 3
непрочитанных (чужих): 2
```

## Задание 3 — свой BehaviorSubject

Файл: `task-3-behavior-subject.ts`

Реализуй `BehaviorSubject<T>` — вариант Subject, который помнит последнее значение и отдаёт его сразу при подписке. Это самая частая конструкция в Angular-сервисах: компонент, созданный позже, должен увидеть актуальное состояние, а не пустоту.

Что сделать:

- конструктор принимает начальное значение и обязателен;
- при подписке новый наблюдатель немедленно получает текущее значение, до всяких новых `next`;
- `getValue()` возвращает текущее значение без подписки;
- `next(value)` обновляет текущее значение и рассылает его подписчикам.

Реализуй через наследование от `Subject<T>` из задания 1 — переопредели `subscribe` и `next`, не копируя код рассылки.

**Критерии**

- Подписка после нескольких `next` сразу получает **последнее** значение, а не всю историю и не пустоту.
- `getValue()` возвращает то же значение, что пришло последнему подписчику.
- Наследование настоящее: рассылка не дублируется, `next` из родителя переиспользован.
- Сравни поведение с заданием 1 и своими словами сформулируй, в каком случае в чате нужен `Subject`, а в каком `BehaviorSubject`.

**Ожидаемый вывод**

```
подписчик 1 получил: general
подписчик 1 получил: random
подписчик 2 получил: random
getValue(): random
подписчик 1 получил: dev
подписчик 2 получил: dev
```

Ключевая строка — третья: второй подписчик пришёл позже, но состояние получил сразу.
