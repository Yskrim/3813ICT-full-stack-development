## Задача

Observable — не единственный способ работать с асинхронностью. В самом JavaScript есть Promise, а поверх него — `async`/`await` и `fetch`. На сервере Node.js промисы встречаются постоянно, а в Angular иногда приходится переводить одно в другое.

У промисов есть три ловушки, из-за которых код работает не так, как ожидаешь. Во-первых, `fetch` не считает 404 ошибкой. Во-вторых, два `await` подряд выполняются по очереди, даже когда могли бы идти одновременно. В-третьих, `from(fetch(...))` отправляет запрос раньше, чем на него подписались. В этом задании ты воспроизведёшь каждую и научишься её обходить. Сервер из подготовки пишет каждый запрос в консоль — по ней будет видно, когда запросы уходят на самом деле.

## Зачем это задание

Эти ошибки не падают с понятным сообщением — они дают «странное» поведение: пустые данные, медленную загрузку, лишние запросы. Если один раз увидеть их намеренно, потом они узнаются сразу.

## Что проверяет

1. Ты получаешь данные из `fetch` через `response.json()` и проверяешь `response.ok`.
2. Ты обрабатываешь ошибки в `async`-функциях через `try/catch`.
3. Ты различаешь последовательный и параллельный запуск (`Promise.all`).
4. Ты понимаешь, что Promise запускается сразу, а `defer` делает запуск ленивым; знаешь `firstValueFrom`.

## Старт

Файл `src/app/pages/lab/promise-lab.ts`, опыты — кнопками в `LabComponent`. Сервер запущен (`npm run dev`), его консоль держи на виду. Наблюдения — в `observations.md`.

Вспомогательная функция для опытов со временем:

```ts
export const wait = <T>(ms: number, value: T) =>
  new Promise<T>((resolve) => setTimeout(() => resolve(value), ms));
```

## Что сделать

**Часть А — fetch как следует**

1. Напиши `async`-функцию `getJson<T>(url)`: запрос через `fetch`, ошибка, если ответ не 2xx, иначе разобранный JSON.
2. Вызови её для `http://localhost:3000/api/health`, для несуществующего `http://localhost:3000/api/nope` и при остановленном сервере. Что приходит в каждом случае и где это ловится?
3. Для сравнения выведи `response.body` из первого запроса — что там на самом деле?

**Часть Б — последовательно и параллельно**

1. Две операции: `wait(1500, 'slow')` и `wait(1000, 'fast')`. Замерь время для двух `await` подряд и для `Promise.all`.
2. То же с двумя настоящими запросами к `/api/slow`. Посмотри в консоль сервера: когда пришёл второй запрос в каждом варианте?

**Часть В — Promise и Observable**

1. Создай `from(fetch('http://localhost:3000/api/health'))`, **не подписываясь**. Есть ли запрос в консоли сервера?
2. Создай `defer(() => fetch('http://localhost:3000/api/health'))`, не подписываясь, а потом подпишись дважды. Сколько запросов и когда?
3. Получи одно значение из Observable в `async`-функции через `firstValueFrom`.

## Критерии готовности

## Типичные ловушки

- `response.body` вместо `await response.json()`.
- `catch` только для сетевых ошибок, без проверки `response.ok`.
- `toPromise()` — устарел, вместо него `firstValueFrom` / `lastValueFrom`.
