## 1. Что такое директивы

Шаблон Angular выглядит как HTML, но умеет гораздо больше: показывать элемент по условию, повторять его для каждого элемента массива, менять стиль в зависимости от данных. Обычный HTML этого не может — эти возможности добавляют **директивы**. Эта тема о том, какие они бывают и как ими пользоваться.

**Директива** — это класс, который добавляет HTML-элементам новое поведение или новый синтаксис в шаблоне.

Директивы бывают трёх видов:

| Вид | Что делает | Примеры |
|---|---|---|
| **Компонент** | директива со своим шаблоном — «кусок интерфейса» | `<app-header>`, `<app-message-box>` |
| **Структурная** | меняет структуру DOM: добавляет и убирает элементы | `*ngIf`, `*ngFor` (сейчас — `@if`, `@for`) |
| **Атрибутная** | меняет внешний вид или поведение существующего элемента | `[ngClass]`, `[ngStyle]`, `[(ngModel)]`, свои директивы |

Структурные директивы долгое время были единственным способом писать условия и циклы в шаблоне. Сейчас для этого есть встроенный синтаксис — с него и начнём, а старые директивы разберём после: они встречаются в материалах курса и в существующем коде.

## 2. Встроенный синтаксис управления

С Angular 17 условия и циклы пишут прямо в шаблоне блоками, которые начинаются с `@`. Это **control flow** (синтаксис управления потоком). Он заменяет старые структурные директивы: короче, быстрее и не требует импортов. ⚠ [П-1](5_5-templating-popravki.md#p-1)

Все блоки пишутся **строчными буквами**: `@if`, `@for`, `@switch`.

<a id="s2-1"></a>

### 2.1 `@if` — показать по условию

`@if` добавляет содержимое в DOM, только если условие истинно. Если ложно — содержимого нет в DOM вообще (а не просто скрыто стилем).

```html
@if (messages().length === 0) {
  <p>Сообщений пока нет</p>
} @else if (messages().length === 1) {
  <p>Одно сообщение</p>
} @else {
  <p>Сообщений: {{ messages().length }}</p>
}
```

- Ветки: `@if`, сколько угодно `@else if` (два слова, через пробел), одна необязательная `@else`.
- **`as`** сохраняет результат условия в переменную — удобно для сигналов и значений, которые могут быть `null`:

```html
@if (auth.currentUser(); as user) {
  <span>Привет, {{ user.username }}</span>   <!-- внутри блока user точно не null -->
}
```

<a id="s2-2"></a>

### 2.2 `@for` — повторить для каждого элемента

`@for` выводит содержимое для каждого элемента коллекции. У него обязательное выражение **`track`**.

```html
<ul>
  @for (msg of messages(); track msg.id) {
    <li>{{ $index + 1 }}. {{ msg.text }}</li>
  } @empty {
    <li>В канале пока пусто</li>
  }
</ul>
```

- **`track`** говорит Angular, как отличать элементы друг от друга. Когда список меняется, Angular по этому ключу понимает, какие строки остались, какие добавились и какие удалились, и не пересоздаёт DOM для тех, что остались. Обычно это `id`; для неизменного списка без `id` — `track $index`.
- **`@empty`** — часть блока `@for`: показывается, если коллекция пуста.
- **Встроенные переменные** внутри `@for`:

| Переменная | Значение |
|---|---|
| `$index` | номер элемента, с нуля |
| `$count` | количество элементов |
| `$first`, `$last` | первый или последний элемент |
| `$even`, `$odd` | чётный или нечётный номер |

Переменную можно переименовать: `@for (m of messages(); track m.id; let i = $index, last = $last)`.

<a id="s2-3"></a>

### 2.3 `@switch` — один вариант из нескольких

`@switch` сравнивает значение с вариантами и показывает первый совпавший. Если не совпал ни один — `@default`.

```html
@switch (msg.type) {
  @case ('image') {
    <img [src]="msg.imageUrl" alt="">
  }
  @case ('system') {
    <em>{{ msg.text }}</em>
  }
  @default {
    <span>{{ msg.text }}</span>
  }
}
```

Сравнение строгое (`===`), и «проваливания» в следующий `@case`, как в JavaScript `switch`, нет.

<a id="s2-4"></a>

### 2.4 `@let` — переменная в шаблоне

С Angular 18.1 можно объявить переменную прямо в шаблоне, чтобы не повторять длинное выражение:

```html
@let user = auth.currentUser();
@let isAdmin = user?.role === 'superadmin';

@if (isAdmin) {
  <button>Удалить группу</button>
}
```

<a id="s2-5"></a>

### 2.5 Пример из материала

Вот как встроенный синтаксис показан в материале курса:

```html
@if (name=='Allan') {
<p>Welcome Allan</p>
} @else {
<p> Welcome</p>
}
```

**Что в нём происходит.** Если в поле компонента `name` строка `'Allan'`, показывается «Welcome Allan», иначе — «Welcome». Пример верный.

Дальше в материале перечислены варианты: `@If`, `@If / @else`, `@If / @elseif / @else`, `@for`, `@switch`, `@empty`. Названия там записаны с ошибками: блоки пишутся со строчной буквы (`@if`), а ветка «иначе если» — двумя словами (`@else if`). Также не сказано, что у `@for` обязателен `track`, а `@empty` работает только внутри `@for`. ⚠ [П-1](5_5-templating-popravki.md#p-1)

Вот тот же пример в рекомендуемом стиле — со строгим сравнением и веткой `@else if`:

```html
@if (name === 'Allan') {
  <p>Welcome Allan</p>
} @else if (name) {
  <p>Welcome, {{ name }}</p>
} @else {
  <p>Welcome</p>
}
```

**Какая последовательность?**

1. **Angular вычисляет условие** `name === 'Allan'`.
   1. Если `true` — в DOM добавляется первый `<p>`, остальные ветки не проверяются.
2. **Иначе проверяется `@else if (name)`.**
   1. Непустая строка — истина: добавляется приветствие с именем.
3. **Иначе — `@else`**: общее приветствие.
4. **Когда `name` меняется**, Angular снова проверяет условия и заменяет содержимое: старая ветка убирается из DOM, новая добавляется.

## 3. Старые структурные директивы

До Angular 17 условия и циклы писали директивами `*ngIf`, `*ngFor`, `[ngSwitch]`. Их нужно уметь читать: они есть в материалах курса, в старом коде и во многих ответах на форумах. Принципы у них те же, что у нового синтаксиса. Чтобы понять, как они устроены, сначала разберём два вспомогательных элемента.

<a id="s3-1"></a>

### 3.1 `<ng-template>`

**`<ng-template>`** — элемент Angular, который описывает кусок разметки, но **сам по себе его не отрисовывает**. Содержимое появится в DOM, только когда какая-то директива явно попросит его вывести. ⚠ [П-8](5_5-templating-popravki.md#p-8)

Вот пример из материала:

```html
<ng-template [ngIf]="isLoggedIn">
  <div>Welcome back, friend.</div>
</ng-template>
```

Директива `ngIf` здесь решает, выводить шаблон или нет. Без директивы `<ng-template>` просто ничего бы не показал.

<a id="s3-2"></a>

### 3.2 `<ng-container>`

**`<ng-container>`** — «невидимая обёртка»: группирует элементы и может нести директиву, но сам в DOM не попадает.

Зачем он нужен: на одном элементе может быть **только одна** структурная директива. Так нельзя:

```html
<div *ngIf="todos" *ngFor="let todo of todos">
  {{ todo.content }}
</div>
```

А так можно — условие на невидимой обёртке, цикл внутри:

```html
<ng-container *ngIf="todos">
  <div *ngFor="let todo of todos">{{ todo.content }}</div>
</ng-container>
```

С новым синтаксисом эта проблема исчезла: блоки `@if` и `@for` просто вкладываются друг в друга.

<a id="s3-3"></a>

### 3.3 `*ngIf`

`*ngIf` добавляет элемент в DOM, если условие истинно, и убирает, если ложно.

Звёздочка — сокращение. Angular разворачивает её в `<ng-template>` с привязкой `[ngIf]`:

```html
<!-- Сокращённая запись -->
<div *ngIf="show">Some Text</div>

<!-- Во что её разворачивает Angular -->
<ng-template [ngIf]="show">
  <div>Some Text</div>
</ng-template>
```

**`else`** ссылается на именованный `<ng-template>` — он покажется, если условие ложно:

```html
<div *ngIf="show; else option2">Some Text</div>

<ng-template #option2>
  <div>Other Text</div>
</ng-template>
```

**`then` и `else`** — оба варианта вынесены в шаблоны, а элемент с `*ngIf` становится просто «носителем» директивы без своего содержимого. В материале в этом примере имя шаблона записано с пробелом (`option 1`) — так оно не сработает, имя должно быть одним словом. ⚠ [П-2](5_5-templating-popravki.md#p-2)

```html
<div *ngIf="show; then option1 else option2"></div>
<ng-template #option1><div>Show is true</div></ng-template>
<ng-template #option2><div>Show is false</div></ng-template>
```

<a id="s3-4"></a>

### 3.4 `*ngFor`

`*ngFor` повторяет элемент для каждого элемента массива.

```html
<li *ngFor="let item of items">{{ item.name }}</li>
```

Запись внутри кавычек — **микросинтаксис**: `let item of items` означает «возьми каждый элемент `items`, положи в переменную `item` и сделай её доступной в разметке этого повторения». Переменная `item` видна только внутри своей копии элемента.

Как в `forEach`, есть доступ к элементу, а как в обычном `for` — к номеру и количеству:

```html
<li *ngFor="let item of items; let i = index; let c = count">
  {{ i + 1 }} of {{ c }} — {{ item.name }}
</li>
```

Доступные переменные: `index`, `count`, `first`, `last`, `even`, `odd`. Аналог `track` у `*ngFor` — необязательная функция `trackBy`.

<a id="s3-5"></a>

### 3.5 `ngSwitch`

`ngSwitch` показывает один вариант из нескольких. Устроен из трёх частей:

- **`[ngSwitch]`** — атрибутная директива на обёртке: берёт значение из компонента (поэтому в квадратных скобках);
- **`*ngSwitchCase`** — структурная директива: показывает элемент, если значение совпало;
- **`*ngSwitchDefault`** — вариант по умолчанию.

```html
<div [ngSwitch]="item.color">
  <app-color-red   *ngSwitchCase="'red'"></app-color-red>
  <app-color-green *ngSwitchCase="'green'"></app-color-green>
  <app-color       *ngSwitchDefault></app-color>
</div>
```

Обрати внимание на кавычки: `"'red'"` — внешние кавычки HTML-атрибута, внутренние — строка TypeScript. В материале здесь опечатка: `'gree'` вместо `'green'`, поэтому зелёный вариант никогда не совпадёт. ⚠ [П-3](5_5-templating-popravki.md#p-3)

<a id="s3-6"></a>

### 3.6 Старое → новое

Вот соответствие старых директив и нового синтаксиса:

| Старое | Новое |
|---|---|
| `<div *ngIf="cond">` | `@if (cond) { <div> }` |
| `*ngIf="cond; else other"` + `<ng-template #other>` | `@if (cond) { ... } @else { ... }` |
| `*ngIf="user$ \| async as user"` | `@if (user(); as user) { ... }` |
| `*ngFor="let x of list; trackBy: fn"` | `@for (x of list; track x.id) { ... }` |
| `let i = index` | `$index` |
| пустой список — отдельный `*ngIf` | `@empty { ... }` |
| `[ngSwitch]` + `*ngSwitchCase` + `*ngSwitchDefault` | `@switch` + `@case` + `@default` |
| `<ng-container>` ради двух директив | просто вложенные блоки |

**Импорты.** Старым директивам в standalone-компоненте нужен импорт: `imports: [NgIf, NgFor]` или `imports: [CommonModule]`. Без него `*ngFor` не сработает. Новым блокам импорт не нужен. ⚠ [П-7](5_5-templating-popravki.md#p-7)

Старый шаблон можно перевести на новый синтаксис автоматически: `ng generate @angular/core:control-flow`. Пример — в [примерах, пример 4](5_5-templating-primery.md#ex-4).

## 4. Привязки

Директивы работают вместе с **привязками** — способами связать шаблон с классом компонента. Их четыре, и у каждой свои скобки.

<a id="s4-1"></a>

### 4.1 Интерполяция `{{ }}`

Выводит значение как текст: `<p>{{ user.username }}</p>`. Angular экранирует HTML, поэтому `<script>` в данных покажется как текст ([5_1 §7.3](5_1-data-persistence-konspekt.md#s7-3)).

<a id="s4-2"></a>

### 4.2 Привязка свойства `[ ]`

**Привязка свойства** (property binding) — передача данных из класса компонента в свойство элемента шаблона. Она **односторонняя**: из класса в шаблон.

```html
<img [src]="msg.imageUrl" [alt]="msg.author">
<button [disabled]="!newName.trim()">Создать</button>
<app-message-box [channelId]="channel.id" />      <!-- в @Input дочернего компонента -->
```

Отличие от интерполяции: `[src]="url"` передаёт значение любого типа (число, объект, `true`/`false`), а `src="{{ url }}"` — всегда строку. Для `disabled` это важно: строка `"false"` — истина.

<a id="s4-3"></a>

### 4.3 Привязка события `( )`

**Привязка события** (event binding) — вызов метода класса, когда в шаблоне что-то происходит. Направление — из шаблона в класс.

```html
<button (click)="save()">Сохранить</button>
<input (input)="onType($event)">                     <!-- $event — объект события -->
<input (keydown.enter)="send()">                     <!-- только клавиша Enter -->
```

<a id="s4-4"></a>

### 4.4 Двусторонняя привязка `[( )]`

`[(ngModel)]` связывает поле ввода и переменную **в обе стороны**: изменил переменную — поменялось поле, ввёл текст — поменялась переменная. Запись `[( )]` называют «банан в коробке» (banana in a box): квадратные скобки — данные в шаблон, круглые — событие из шаблона.

Это сокращение двух привязок:

```html
<!-- Сокращённо -->
<input [(ngModel)]="name">

<!-- То же самое полностью -->
<input [ngModel]="name" (ngModelChange)="name = $event">
```

Для `ngModel` нужен `FormsModule` в `imports` компонента (`import { FormsModule } from '@angular/forms'`).

## 5. Атрибутные директивы

Атрибутная директива ничего не добавляет и не убирает — она меняет внешний вид или поведение элемента, на котором стоит. Вот встроенные из материала:

- **`[ngClass]`** — добавляет и убирает набор CSS-классов;
- **`[ngStyle]`** — добавляет и убирает набор inline-стилей;
- **`[(ngModel)]`** — двусторонняя привязка к полю формы ([§4.4](#s4-4)).

```html
<li [ngClass]="{ own: isOwn, unread: !msg.read }">...</li>
<div [ngStyle]="{ 'background-color': color, width: width + 'px' }">...</div>
```

Сейчас для классов и стилей чаще используют встроенные **привязки `class` и `style`** — им не нужен импорт, и Angular рекомендует их вместо `ngClass`/`ngStyle`: ⚠ [П-4](5_5-templating-popravki.md#p-4)

```html
<li [class.own]="isOwn">...</li>                        <!-- один класс по условию -->
<li [class]="{ own: isOwn, unread: !msg.read }">...</li> <!-- несколько классов объектом -->
<div [style.width.px]="width">...</div>                   <!-- стиль с единицей измерения -->
<div [style.background-color]="color">...</div>
```

## 6. Своя атрибутная директива

Встроенных директив хватает не всегда. Если одно и то же поведение нужно многим элементам (подсветка при наведении, автофокус, проверка прав), его выносят в свою директиву и подключают одним атрибутом.

**Создание через CLI:** ⚠ [П-5](5_5-templating-popravki.md#p-5)

```bash
ng generate directive highlight      # коротко: ng g d highlight
```

CLI добавляет к селектору префикс `app`, чтобы директива не совпала с существующими HTML-атрибутами: селектор будет `[appHighlight]`. Имена файла и класса зависят от версии, как и у сервисов ([5_2 §3.2](5_2-services-konspekt.md#s3-2)): в проектах Angular 20+ — `highlight.ts` и класс `Highlight`, в более ранних — `highlight.directive.ts` и `HighlightDirective`.

Вот пример того, как выглядит директива, которая подсвечивает элемент при наведении мыши:

```ts
// highlight.directive.ts
import { Directive, ElementRef, inject, input } from '@angular/core';

@Directive({
  selector: '[appHighlight]',             // срабатывает на элементах с атрибутом appHighlight
  host: {                                 // события элемента, на котором стоит директива
    '(mouseenter)': 'paint(true)',
    '(mouseleave)': 'paint(false)',
  },
})
export class HighlightDirective {
  private el = inject<ElementRef<HTMLElement>>(ElementRef);   // сам элемент
  // Входной параметр с тем же именем, что и селектор: <p [appHighlight]="'#e0f0ff'">
  readonly color = input('', { alias: 'appHighlight' });

  paint(on: boolean): void {
    this.el.nativeElement.style.backgroundColor = on ? this.color() || '#fff3c4' : '';
  }
}
```

```html
<!-- в шаблоне компонента, у которого HighlightDirective есть в imports -->
<p appHighlight>Подсветится жёлтым</p>
<p [appHighlight]="'#e0f0ff'">Подсветится голубым</p>
```

**Какая последовательность?**

1. **Angular видит атрибут `appHighlight`** на `<p>` и создаёт экземпляр директивы для этого элемента.
   1. `inject(ElementRef)` даёт директиве ссылку на сам `<p>`.
   2. Входной параметр `color` получает значение атрибута: пустую строку или `'#e0f0ff'`.
2. **Пользователь наводит мышь** — срабатывает событие `mouseenter`, описанное в `host`.
   1. Вызывается `paint(true)`: фон элемента становится цветом из параметра или жёлтым по умолчанию.
3. **Мышь уходит** — `mouseleave` → `paint(false)`: фон сбрасывается.

Директиву, как и компонент, нужно добавить в `imports` того компонента, в шаблоне которого она используется.

## 7. Шаблонные переменные

Иногда нужно обратиться к элементу шаблона прямо из шаблона — например, передать в метод текст из поля ввода, не заводя под него переменную в классе. Для этого есть шаблонные переменные.

**Шаблонная переменная** (template reference variable) — имя, которое даётся элементу шаблона через `#`, чтобы ссылаться на него в других местах шаблона.

Вот пример из материала:

```html
<input type="text" #zipcode>
<button (click)="location(zipcode.value)">show</button>
```

`#zipcode` объявляет переменную, указывающую на элемент `<input>`. Кнопка по клику берёт его текущее значение `zipcode.value` и передаёт в метод `location` компонента.

**Что может лежать в переменной:**

- на обычном HTML-элементе — сам DOM-элемент (как `<input>` выше);
- на компоненте — экземпляр компонента;
- на `<ng-template>` — сам шаблон (так работали `else option2` в [§3.3](#s3-3)).

**Область видимости.** Переменная видна во всём шаблоне, **кроме** случаев, когда она объявлена внутри блока (`@if`, `@for`, `<ng-template>`): тогда она видна только внутри этого блока. Например, в `@for` у каждого повторения своя переменная — это удобно для полей ввода в каждой строке списка. Одно имя в одной области объявляют один раз. ⚠ [П-6](5_5-templating-popravki.md#p-6)

Вместо `#` когда-то можно было писать префикс `ref-` (`ref-zipcode`). В актуальной документации этой формы нет — используй `#`.

## 9. Ключевые факты

**Директивы**

- Три вида: компоненты (со своим шаблоном), структурные (добавляют и убирают элементы), атрибутные (меняют вид или поведение).

**Встроенный синтаксис**

- `@if` / `@else if` / `@else` — строчными буквами; `as` сохраняет значение условия.
- `@for (x of list; track x.id)` — `track` обязателен; `@empty` — часть `@for`.
- Переменные `@for`: `$index`, `$count`, `$first`, `$last`, `$even`, `$odd`.
- `@switch` / `@case` / `@default`; сравнение строгое, проваливания нет.
- `@let` объявляет переменную в шаблоне (Angular 18.1+).
- Встроенным блокам импорт не нужен.

**Старые директивы**

- `<ng-template>` описывает разметку, но не рисует её сам; `<ng-container>` — невидимая обёртка.
- На одном элементе — одна структурная директива.
- `*ngIf` разворачивается в `<ng-template [ngIf]>`; `else` и `then` ссылаются на именованные шаблоны.
- `*ngFor="let x of list; let i = index"`; `[ngSwitch]` + `*ngSwitchCase` + `*ngSwitchDefault`.
- В standalone-компоненте им нужен импорт `NgIf`, `NgFor` или `CommonModule`.

**Привязки**

- `{{ }}` — текст; `[prop]` — из класса в свойство элемента; `(event)` — из шаблона в метод; `[(ngModel)]` — в обе стороны.
- `[(ngModel)]` = `[ngModel]` + `(ngModelChange)`; нужен `FormsModule`.

**Атрибутные директивы**

- `[ngClass]`, `[ngStyle]`, `[(ngModel)]`; для классов и стилей рекомендуют `[class.x]`, `[class]`, `[style.x]`.
- Своя директива: `ng g d highlight` → селектор `[appHighlight]`; подключается в `imports`.

**Шаблонные переменные**

- `#name` на элементе; значение — DOM-элемент, компонент или шаблон.
- Внутри `@if`, `@for`, `<ng-template>` переменная видна только в этом блоке.
