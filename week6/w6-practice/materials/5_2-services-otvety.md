## A. Зачем нужны сервисы

<a id="a-1"></a>

### 1. Какую проблему решают сервисы

**Ответ:** сервис — это класс с общей логикой или общими данными, который Angular сам создаёт и передаёт компонентам, которым он нужен. Три задачи:

1. **убирает дублирование** — код пишется один раз;
2. **делит данные между компонентами** — все получают один экземпляр и видят одни данные;
3. **разделяет обязанности** — компонент показывает, сервис отвечает за данные, логику и связь с сервером и хранилищем.

**Подробнее:** [Конспект §1.2](5_2-services-konspekt.md#s1-2) · [← вопрос](5_2-services-voprosy.md#q-1)

<a id="a-2"></a>

### 2. Web API

**Ответ:** Web API — набор адресов (маршрутов) веб-сервера, которые принимают параметры и возвращают результат, чаще всего в JSON. Чтобы обратиться к нему, нужно знать адрес, передать параметры и разобрать пришедший ответ.

**Пояснение:** именно этот код (адрес, параметры, разбор ответа) и не стоит повторять в каждом компоненте — его выносят в сервис.

**Подробнее:** [Конспект §1.1](5_2-services-konspekt.md#s1-1) · [← вопрос](5_2-services-voprosy.md#q-2)

<a id="a-3"></a>

### 3. Что выносят в сервисы

**Ответ:**

- запросы к серверу (Web API);
- работу с хранилищами (localStorage, sessionStorage, куки, IndexedDB);
- общую логику: проверку прав, вычисления, форматирование;
- общее состояние: текущий пользователь, открытый канал, список групп.

**Подробнее:** [Конспект §1.2](5_2-services-konspekt.md#s1-2) · [Конспект §7](5_2-services-konspekt.md#s7) · [← вопрос](5_2-services-voprosy.md#q-3)

## B. Внедрение зависимостей

<a id="a-4"></a>

### 4. Зависимость и её внедрение

**Ответ:** зависимость — объект, который нужен классу для работы (например, `BookService` для компонента списка книг). Внедрение зависимостей — подход, при котором класс не создаёт зависимости сам, а получает их готовыми снаружи. В Angular их создаёт и выдаёт **инжектор**.

**Подробнее:** [Конспект §2.1](5_2-services-konspekt.md#s2-1) · [← вопрос](5_2-services-voprosy.md#q-4)

<a id="a-5"></a>

### 5. Почему не `new`

**Ответ:**

1. **Нет общего состояния** — каждый `new` создаёт отдельный объект, и у каждого компонента свои данные.
2. **Зависимости сервиса — вручную** — если сервису нужен, например, `HttpClient`, его тоже пришлось бы создавать в каждом компоненте.
3. **Нельзя подменить в тестах** — сервис «зашит» в компонент.

**Пояснение:** правильно — `private bookService = inject(BookService);`, тогда Angular выдаст общий экземпляр.

**Подробнее:** [Конспект §2.2](5_2-services-konspekt.md#s2-2) · [Пример 5, подмена реализации](5_2-services-primery.md#ex-5) · [← вопрос](5_2-services-voprosy.md#q-5)

<a id="a-6"></a>

### 6. Термины

**Ответ:**

- **Инжектор** — механизм Angular, который создаёт зависимости, хранит их и выдаёт по запросу.
- **Провайдер** — инструкция для инжектора, как создать зависимость (`providedIn: 'root'`, `providers: [...]`, `{ provide, useClass }`).
- **Токен** — ключ, по которому запрашивают зависимость; обычно сам класс сервиса.

**Подробнее:** [Конспект §2.1](5_2-services-konspekt.md#s2-1) · [← вопрос](5_2-services-voprosy.md#q-6)

<a id="a-7"></a>

### 7. Два компонента просят один сервис

**Ответ:**

1. `CatalogComponent` просит `BookService` → инжектор видит, что экземпляра нет → создаёт его, запоминает и отдаёт.
2. `SearchComponent` просит `BookService` → инжектор видит, что экземпляр уже есть → отдаёт **тот же самый**.

**Подробнее:** [Конспект §2.3, диаграмма](5_2-services-konspekt.md#s2-3) · [← вопрос](5_2-services-voprosy.md#q-7)

## C. Создание сервиса

<a id="a-8"></a>

### 8. `@Injectable` и `providedIn: 'root'`

**Ответ:** `@Injectable` помечает класс как то, что инжектор умеет создавать и внедрять. `providedIn: 'root'` регистрирует сервис в корневом инжекторе и даёт:

1. один экземпляр на всё приложение;
2. доступность в любом компоненте без дополнительной настройки;
3. tree-shaking — неиспользуемый сервис не попадает в сборку.

**Подробнее:** [Конспект §3.1](5_2-services-konspekt.md#s3-1) · [П-3](5_2-services-popravki.md#p-3) · [← вопрос](5_2-services-voprosy.md#q-8)

<a id="a-9"></a>

### 9. Что создаст CLI

**Ответ:** зависит от версии Angular, в которой создан проект:

- проект Angular 20 и новее — `src/app/services/book.ts`, класс `Book`;
- более ранний или обновлённый через `ng update` — `src/app/services/book.service.ts`, класс `BookService`.

**Пояснение:** быстрая проверка — корневой компонент лежит в `app.ts` (без суффиксов) или в `app.component.ts` (с суффиксами). Суффикс можно получить флагом `--type=service`.

**Подробнее:** [Конспект §3.2](5_2-services-konspekt.md#s3-2) · [П-4](5_2-services-popravki.md#p-4) · [← вопрос](5_2-services-voprosy.md#q-9)

<a id="a-10"></a>

### 10. `@Injectable()` без `providedIn`

**Ответ:** класс можно внедрять, но сам он нигде не зарегистрирован — его подключают в `providers` компонента или маршрута там, где он нужен. Если компонент попросит такой сервис, а он не указан ни в одних `providers` по пути к корню, Angular выдаст ошибку `NullInjectorError: No provider for DraftService`.

**Подробнее:** [П-2](5_2-services-popravki.md#p-2) · [Пример 4, последний абзац](5_2-services-primery.md#ex-4) · [← вопрос](5_2-services-voprosy.md#q-10)

## D. Внедрение в компонент

<a id="a-11"></a>

### 11. Перепиши на `inject()`

**Ответ:**

```ts
import { inject } from '@angular/core';
import { Router } from '@angular/router';

export class BookListComponent {
  private bookService = inject(BookService);
  private router = inject(Router);
}
```

**Пояснение:** конструктор больше не нужен, каждая зависимость — отдельное поле.

**Подробнее:** [Конспект §4.2](5_2-services-konspekt.md#s4-2) · [← вопрос](5_2-services-voprosy.md#q-11)

<a id="a-12"></a>

### 12. `private` в параметре конструктора

**Ответ:** это сокращение TypeScript: оно одновременно объявляет поле класса и присваивает ему переданное значение.

```ts
// Сокращённо
constructor(private bookService: BookService) {}

// Развёрнуто
private bookService: BookService;
constructor(bookService: BookService) {
  this.bookService = bookService;
}
```

**Подробнее:** [Конспект §4.1](5_2-services-konspekt.md#s4-1) · [← вопрос](5_2-services-voprosy.md#q-12)

<a id="a-13"></a>

### 13. `inject()` в методе

**Ответ:** при клике будет ошибка `NG0203`: `inject()` вызван вне контекста внедрения — обычный метод им не является. Исправление — вынести зависимость в поле класса:

```ts
export class GroupsComponent {
  private groupService = inject(GroupService);   // поле — контекст внедрения

  onDelete(id: number): void {
    this.groupService.remove(id).subscribe();
  }
}
```

**Подробнее:** [Конспект §4.2](5_2-services-konspekt.md#s4-2) · [П-7](5_2-services-popravki.md#p-7) · [← вопрос](5_2-services-voprosy.md#q-13)

<a id="a-14"></a>

### 14. Где работает `inject()`

**Ответ:** в контексте внедрения:

- в инициализаторах полей класса;
- в конструкторе;
- в функциях, которые Angular вызывает сам: функциональных гардах, резолверах, фабриках провайдеров.

Современное руководство по стилю Angular рекомендует `inject()`, а не параметры конструктора.

**Подробнее:** [Конспект §4.2](5_2-services-konspekt.md#s4-2) · [Конспект §4.3](5_2-services-konspekt.md#s4-3) · [← вопрос](5_2-services-voprosy.md#q-14)

<a id="a-15"></a>

### 15. Сервис в шаблоне

**Ответ:** не скомпилируется: шаблон не может обращаться к `private`-полю. Нужен `protected auth = inject(AuthService);` — поле доступно шаблону, но не другим классам.

**Пояснение:** правило — если шаблон использует сервис, `protected`; если нет — `private`. `public` открывает поле всем, это обычно лишнее.

**Подробнее:** [Конспект §4.4](5_2-services-konspekt.md#s4-4) · [П-6](5_2-services-popravki.md#p-6) · [← вопрос](5_2-services-voprosy.md#q-15)

<a id="a-16"></a>

### 16. Ошибки в `listBook()`

**Ответ:**

1. нет `const`/`let` — `books:` воспринимается как метка JavaScript, и строка становится синтаксической ошибкой;
2. тип `Books` не объявлен — модель книги обычно называется `Book`, массив — `Book[]`;
3. локальная переменная не попадёт в шаблон — нужно поле класса.

```ts
books: Book[] = [];

listBooks(): void {
  const books: Book[] = this.bookService.getBooks();
  this.books = books;
}
```

**Подробнее:** [Конспект §4.5](5_2-services-konspekt.md#s4-5) · [П-5](5_2-services-popravki.md#p-5) · [← вопрос](5_2-services-voprosy.md#q-16)

## E. Singleton и области видимости

<a id="a-17"></a>

### 17. Singleton

**Ответ:** singleton — класс, у которого в приложении ровно один экземпляр, и все пользуются им. Раз объект один, данные в нём общие: изменение, сделанное через сервис в одном компоненте, видно во всех остальных.

**Подробнее:** [Конспект §5.1](5_2-services-konspekt.md#s5-1) · [Пример 1](5_2-services-primery.md#ex-1) · [← вопрос](5_2-services-voprosy.md#q-17)

<a id="a-18"></a>

### 18. Когда появится строка в консоли

**Ответ:**

- а) ничего — сервис никому не нужен и не создан;
- б) «BookService создан» — первый `inject`;
- в) ничего — экземпляр уже есть, его переиспользуют;
- г) «BookService создан» снова — перезагрузка уничтожила всё, приложение стартовало заново.

**Пояснение:** сервис с `providedIn: 'root'` создаётся лениво, при первом запросе, а не при старте приложения.

**Подробнее:** [Конспект §5.2](5_2-services-konspekt.md#s5-2) · [П-1](5_2-services-popravki.md#p-1) · [← вопрос](5_2-services-voprosy.md#q-18)

<a id="a-19"></a>

### 19. Данные сервиса после F5

**Ответ:** пропадут: сервис хранит их в памяти JavaScript, а перезагрузка её очищает. Чтобы данные пережили F5, сервис сам сохраняет их в хранилище из темы 5_1 (например, localStorage) и при создании читает оттуда.

**Подробнее:** [Конспект §5.2](5_2-services-konspekt.md#s5-2) · [Пример 2, AuthService](5_2-services-primery.md#ex-2) · [← вопрос](5_2-services-voprosy.md#q-19)

<a id="a-20"></a>

### 20. Сколько экземпляров

**Ответ:**

- а) три — по одному на каждое окно;
- б) экземпляр **своего** окна: у `MessageBoxComponent` сервиса в `providers` нет, поэтому Angular поднимается к родителю и берёт его экземпляр;
- в) он уничтожится вместе с окном, и у сервиса вызовется `ngOnDestroy`.

**Подробнее:** [Конспект §5.3](5_2-services-konspekt.md#s5-3) · [Пример 4](5_2-services-primery.md#ex-4) · [← вопрос](5_2-services-voprosy.md#q-20)

<a id="a-21"></a>

### 21. Где регистрировать

**Ответ:**

- `providedIn: 'root'` — данные или логика общие для всего приложения (большинство сервисов);
- `providers` маршрута — сервис нужен только в одном разделе, и в нём должен быть один экземпляр;
- `providers` компонента — у каждого экземпляра компонента должно быть своё независимое состояние (черновик в каждом окне чата).

**Подробнее:** [Конспект §5.3](5_2-services-konspekt.md#s5-3) · [Схема выбора в примерах](5_2-services-primery.md#ex-0) · [← вопрос](5_2-services-voprosy.md#q-21)

## F. Общие данные в сервисе

<a id="a-22"></a>

### 22. Почему не компилируется

**Ответ:** в новых проектах включён строгий режим TypeScript. Параметры `key` и `item` без типа дают ошибку «implicitly has an 'any' type», а обращение `this.jsonItems[key]` к объекту типа `{}` — ошибку индексации. Исправление:

```ts
@Injectable({ providedIn: 'root' })
export class DataService {
  private items: Record<string, string> = {};

  setItem(key: string, value: string): void {
    this.items[key] = value;
  }

  getItem(key: string): string | undefined {
    return this.items[key];
  }
}
```

**Подробнее:** [Конспект §6.2](5_2-services-konspekt.md#s6-2) · [П-8](5_2-services-popravki.md#p-8) · [← вопрос](5_2-services-voprosy.md#q-22)

<a id="a-23"></a>

### 23. NG8002

**Ответ:** standalone-компонент сам перечисляет в `imports` всё, что использует его шаблон. Директива `ngModel` входит в `FormsModule`, а он не подключён. Исправление — `imports: [FormsModule]` в декораторе компонента.

**Подробнее:** [Конспект §6.2](5_2-services-konspekt.md#s6-2) · [П-9](5_2-services-popravki.md#p-9) · [← вопрос](5_2-services-voprosy.md#q-23)

<a id="a-24"></a>

### 24. Закрытые данные

**Ответ:** чтобы данные менялись только через методы сервиса. Если поле публичное, любой компонент может изменить его в обход методов — сервис теряет контроль, а при сигналах ещё и не уведомит остальных. Копия или `asReadonly()` дают прочитать данные, но не испортить их.

**Подробнее:** [Конспект §6.2](5_2-services-konspekt.md#s6-2) · [Конспект §6.3](5_2-services-konspekt.md#s6-3) · [← вопрос](5_2-services-voprosy.md#q-24)

<a id="a-25"></a>

### 25. Почему второй компонент не обновляется

**Ответ:** объект изменён на месте, и в сигнал положена **та же** ссылка. Сигнал сравнивает старое и новое значение по ссылке, видит одно и то же и никого не уведомляет. Нужно создать новый объект:

```ts
setItem(key: string, value: string): void {
  this.items.update((current) => ({ ...current, [key]: value }));
}
```

**Подробнее:** [Конспект §6.3](5_2-services-konspekt.md#s6-3) · [← вопрос](5_2-services-voprosy.md#q-25)

<a id="a-26"></a>

### 26. Что окажется в переменной

**Ответ:** в `books` лежит `Observable`, а не массив: запрос к серверу отвечает не сразу. Массив получают подпиской:

```ts
this.bookService.getBooks().subscribe({
  next: (books) => (this.books = books),
  error: () => (this.error = 'Не удалось загрузить книги'),
});
```

**Пояснение:** без `subscribe()` HttpClient даже не отправит запрос. Подробно — в файле 5_4.

**Подробнее:** [Конспект §3.3](5_2-services-konspekt.md#s3-3) · [П-11](5_2-services-popravki.md#p-11) · [← вопрос](5_2-services-voprosy.md#q-26)

## G. Архитектура и практика

<a id="a-27"></a>

### 27. Разделение обязанностей

**Ответ:**

- общий код — в сервис;
- хранилище и Web API — в сервисах, не в компонентах;
- один сервис — одна обязанность;
- сервис может внедрять другой сервис;
- компонент только показывает данные и передаёт действия пользователя сервисам.

`AuthService` отвечает за вход и выход, а работу с хранилищем поручает `StorageService`. Если хранилище поменяется (или его подменят в тесте), `AuthService` не придётся трогать.

**Подробнее:** [Конспект §7](5_2-services-konspekt.md#s7) · [Пример 2](5_2-services-primery.md#ex-2) · [← вопрос](5_2-services-voprosy.md#q-27)

<a id="a-28"></a>

### 28. Сервис или компонент

**Ответ:**

- а) сервис — запрос к серверу (`ChannelService`);
- б) компонент — чистое отображение (часто вообще CSS `:hover`);
- в) сервис — общая логика (`AuthService.hasRole(...)`), компонент только вызывает её для показа кнопки;
- г) сервис в `providers` компонента окна — своё состояние у каждого окна;
- д) сервис с `providedIn: 'root'` — общее состояние всего приложения.

**Подробнее:** [Конспект §8.1, чек-лист](5_2-services-konspekt.md#s8-1) · [← вопрос](5_2-services-voprosy.md#q-28)

<a id="a-29"></a>

### 29. Экземпляр один?

**Ответ:** добавить `console.log` в конструктор сервиса: при одном экземпляре строка появится один раз за загрузку страницы. Если строка выводится несколько раз, обычно сервис дополнительно указан в `providers` какого-то компонента или маршрута, и там создаётся свой экземпляр.

**Подробнее:** [Конспект §8.2](5_2-services-konspekt.md#s8-2) · [Конспект §5.3](5_2-services-konspekt.md#s5-3) · [← вопрос](5_2-services-voprosy.md#q-29)

<a id="a-30"></a>

### 30. Подмена реализации

**Ответ:** запись говорит инжектору: «по токену `StorageService` выдавай экземпляр `MemoryStorageService`». Все, кто делает `inject(StorageService)`, получат подменённую реализацию, а их код не меняется.

**Пояснение:** главный случай — тесты: проверить `AuthService` без настоящего localStorage и сервера. При `new StorageService()` внутри `AuthService` подменить его было бы невозможно без правки самого `AuthService` — именно поэтому зависимости получают через DI.

**Подробнее:** [Пример 5](5_2-services-primery.md#ex-5) · [Конспект §2.1, провайдер и токен](5_2-services-konspekt.md#s2-1) · [← вопрос](5_2-services-voprosy.md#q-30)
