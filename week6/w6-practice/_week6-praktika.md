**Материалы:** [6_0 — реактивное программирование](../week6/6_0-reactive-programming-konspekt.md) · [6_1 — Observables](../week6/6_1-observables-konspekt.md) · [6_2 — Promise и async](../week6/6_2-promises-async-konspekt.md) · [6_4 — сокет и Observable](../week6/6_4-socket-observable-konspekt.md) · [6_5 — чат](../week6/6_5-socket-chat-konspekt.md) · [6_6 — комнаты](../week6/6_6-socket-rooms-konspekt.md)

Практика идёт от предсказания поведения асинхронного кода к чату, а затем к каналам. Выполняй задания по порядку: третье достраивает чат из второго. Отвечай по памяти; если не знаешь — пиши «не знаю» и только потом открывай материалы. Если ты уже делал вечернюю практику недели 6, задания 2 и 3 можно выполнить в том же проекте.

## Задание 1. Предскажи, что произойдёт

Для каждого фрагмента сначала **запиши предсказание**, потом запусти (в консоли браузера, Node.js или на площадке Angular) и объясни расхождение, если оно есть.

```js
// 1. Два подписчика
let runs = 0;
const cold$ = new Observable((s) => { runs++; s.next(runs); });
cold$.subscribe((v) => console.log('A', v));
cold$.subscribe((v) => console.log('B', v));
const hot = new Subject();
hot.subscribe((v) => console.log('C', v));
hot.subscribe((v) => console.log('D', v));
hot.next(42);

// 2. Отписка
const subject = new Subject();
const sub = subject.subscribe((n) => console.log('first', n));
subject.subscribe((n) => console.log('second', n));
subject.next(1); sub.unsubscribe(); subject.next(2); subject.complete(); subject.next(3);

// 3. fetch и ошибка сервера
fetch('/api/does-not-exist')
  .then((r) => console.log('then', r.status))
  .catch(() => console.log('catch'));

// 4. Сколько секунд?
const wait = (ms) => new Promise((r) => setTimeout(r, ms));
console.time('seq'); await wait(1000); await wait(500); console.timeEnd('seq');
console.time('all'); await Promise.all([wait(1000), wait(500)]); console.timeEnd('all');
```

И ещё: сервер Socket.IO, три клиента A, B, C; A и B вошли в комнату `r1`, событие отправил A. Кто получит событие в каждом случае: `io.emit`, `socket.broadcast.emit`, `socket.to('r1').emit`, `io.to('r1').emit`?

**Готово, если:** для каждого фрагмента записаны предсказание и фактический результат, а для каждого расхождения — объяснение одной фразой. Кроме того, ты можешь сказать, почему фрагмент 3 попадает в `then`, и как отличить «сервер ответил ошибкой» от «сервер недоступен».

Опора: [Subject и Observable](../week6/6_1-observables-konspekt.md#s6-2) · [отписка](../week6/6_1-observables-konspekt.md#s6-3) · [fetch](../week6/6_2-promises-async-konspekt.md#s4) · [ошибки и параллельность](../week6/6_2-promises-async-konspekt.md#s6-4) · [кому уходит сообщение](../week6/6_6-socket-rooms-konspekt.md#s4)

## Задание 2. Собери чат и поймай утечку слушателей

Теперь сделай минимальный чат: сообщение из одной вкладки появляется во всех.

1. **Сервер.** Express и Socket.IO на **одном** HTTP-сервере; CORS для Angular в опциях Socket.IO. Событие `message`: проверить, что пришла непустая строка, и разослать всем, включая отправителя.
2. **Сервис Angular.** Пакет `socket.io-client`, поле сокета с типом `Socket`, одно соединение на приложение, метод отправки и метод, который возвращает `Observable<string>` сообщений.
3. **Компонент.** Форма с `ngSubmit`, список сообщений в сигнале, подписка завершается при уничтожении компонента.

Затем проведи опыт. Временно убери из Observable функцию очистки, трижды перейди со страницы чата на другую и обратно, отправь сообщение. **Предскажи**, сколько раз оно появится, проверь и выведи в консоль число слушателей события `message` на сокете. Потом верни функцию очистки и повтори.

**Готово, если:**

- чат работает в трёх вкладках;
- без функции очистки сообщение дублируется, с ней — нет, и ты записал число слушателей в обоих случаях;
- ты можешь объяснить, почему `httpServer.listen`, а не `app.listen`, и почему функция очистки снимает конкретный обработчик, а не все.

Опора: [сервер чата](../week6/6_5-socket-chat-konspekt.md#s3-2) · [Observable с функцией очистки](../week6/6_4-socket-observable-konspekt.md#s5-2) · [подписка в компоненте](../week6/6_4-socket-observable-konspekt.md#s5-4)

## Задание 3. Раздели чат на каналы

В итоговом проекте сообщение из одного канала не должно попадать в другой. Добавь каналы через комнаты Socket.IO.

1. Три канала: `general`, `random`, `homework`. Клиент **просит** войти в канал событием; сервер проверяет, что канал из списка, выводит сокет из прежнего канала и вводит в новый.
2. Сообщения рассылаются только в текущий канал отправителя — так, чтобы отправитель тоже их видел.
3. Остальным участникам канала — системное сообщение «кто-то вошёл», но не тому, кто вошёл.
4. На клиенте — переключатель каналов; при смене канала лента очищается.

Проверь в трёх вкладках: две в `general`, одна в `random`. Затем из консоли браузера попроси войти в несуществующий канал `admin` и посмотри, что сделал сервер.

**Готово, если:**

- сообщения видят только участники канала, включая отправителя;
- системное сообщение не видит тот, кто вошёл;
- неизвестный канал отклонён, а после переключения сокет не получает сообщения прежнего канала;
- ты можешь объяснить, почему для сообщений нужен `io.to`, а для «кто-то вошёл» — `socket.to`, и почему комнаты при отключении чистить не нужно.

Опора: [комнаты: вход и выход](../week6/6_6-socket-rooms-konspekt.md#s3-2) · [рабочий процесс комнат](../week6/6_6-socket-rooms-konspekt.md#s5-2) · [комнаты в чате Phase 2](../week6/6_6-socket-rooms-konspekt.md#s6)
