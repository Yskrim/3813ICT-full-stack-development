## A. Директивы

<a id="a-1"></a>

### 1. Виды директив

**Ответ:** директива — класс, который добавляет HTML-элементам новое поведение или синтаксис. Виды:

- **компонент** — директива со своим шаблоном: `<app-header>`;
- **структурная** — добавляет и убирает элементы: `*ngIf`, `*ngFor` (сейчас `@if`, `@for`);
- **атрибутная** — меняет вид или поведение элемента: `[ngClass]`, `[(ngModel)]`, `appHighlight`.

**Подробнее:** [Конспект §1](5_5-templating-konspekt.md#s1) · [← вопрос](5_5-templating-voprosy.md#q-1)

## B. Встроенный синтаксис управления

<a id="a-2"></a>

### 2. Ошибки в `@if`

**Ответ:** `@If` — нужно строчными (`@if`); `@elseif` — нужно двумя словами (`@else if`). Сравнение лучше строгое (`===`).

```html
@if (role === 'admin') {
  <p>Админ</p>
} @else if (role === 'user') {
  <p>Пользователь</p>
}
```

**Подробнее:** [Конспект §2.1](5_5-templating-konspekt.md#s2-1) · [П-1](5_5-templating-popravki.md#p-1) · [← вопрос](5_5-templating-voprosy.md#q-2)

<a id="a-3"></a>

### 3. Зачем `track`

**Ответ:** `track` задаёт ключ, по которому Angular отличает элементы. Когда список меняется, Angular по ключу понимает, какие элементы остались, и не пересоздаёт для них DOM. Без `track` шаблон не скомпилируется — он обязателен. Если `id` нет и список не меняется — `track $index`.

**Подробнее:** [Конспект §2.2](5_5-templating-konspekt.md#s2-2) · [Пример 1](5_5-templating-primery.md#ex-1) · [← вопрос](5_5-templating-voprosy.md#q-3)

<a id="a-4"></a>

### 4. `@empty`

**Ответ:** блок, который показывается, если коллекция в `@for` пуста. Пишется только сразу после `@for` — как его часть; отдельно не работает.

**Подробнее:** [Конспект §2.2](5_5-templating-konspekt.md#s2-2) · [← вопрос](5_5-templating-voprosy.md#q-4)

<a id="a-5"></a>

### 5. Переменные `@for`

**Ответ:** `$index`, `$count`, `$first`, `$last`, `$even`, `$odd`.

```html
@for (m of messages; track m.id) {
  <li [class.last]="$last">{{ $index + 1 }}. {{ m.text }}</li>
}
```

**Подробнее:** [Конспект §2.2](5_5-templating-konspekt.md#s2-2) · [← вопрос](5_5-templating-voprosy.md#q-5)

<a id="a-6"></a>

### 6. `@if ... as`

**Ответ:** `as` сохраняет результат условия в переменную. Сигнал вызывается один раз, а внутри блока TypeScript знает, что `user` точно не `null`, — можно писать `user.username` без проверок.

**Подробнее:** [Конспект §2.1](5_5-templating-konspekt.md#s2-1) · [← вопрос](5_5-templating-voprosy.md#q-6)

<a id="a-7"></a>

### 7. `@switch`

**Ответ:** строго (`===`) и показывает первый совпавший `@case`, иначе `@default`. Проваливания нет: выполняется только один вариант, `break` не нужен.

**Подробнее:** [Конспект §2.3](5_5-templating-konspekt.md#s2-3) · [← вопрос](5_5-templating-voprosy.md#q-7)

<a id="a-8"></a>

### 8. `@let`

**Ответ:** объявляет переменную прямо в шаблоне (Angular 18.1+), чтобы не повторять длинное выражение.

```html
@let isAdmin = auth.currentUser()?.role === 'superadmin';
@if (isAdmin) { <button>Удалить</button> }
```

**Подробнее:** [Конспект §2.4](5_5-templating-konspekt.md#s2-4) · [Пример 2](5_5-templating-primery.md#ex-2) · [← вопрос](5_5-templating-voprosy.md#q-8)

## C. Старые структурные директивы

<a id="a-9"></a>

### 9. `<ng-template>`

**Ответ:** нет, никогда. Он только описывает кусок разметки. В DOM содержимое попадает, когда его явно выводит структурная директива (`ngIf`, `ngFor`), `ngTemplateOutlet` или код компонента.

**Подробнее:** [Конспект §3.1](5_5-templating-konspekt.md#s3-1) · [П-8](5_5-templating-popravki.md#p-8) · [← вопрос](5_5-templating-voprosy.md#q-9)

<a id="a-10"></a>

### 10. `<ng-container>`

**Ответ:** невидимая обёртка: группирует элементы и несёт директиву, но в DOM не попадает. На одном элементе может быть только одна структурная директива, поэтому условие ставят на `<ng-container>`, а цикл — на элемент внутри. С `@if`/`@for` проблема исчезла — блоки просто вкладываются.

**Подробнее:** [Конспект §3.2](5_5-templating-konspekt.md#s3-2) · [← вопрос](5_5-templating-voprosy.md#q-10)

<a id="a-11"></a>

### 11. Во что разворачивается звёздочка

**Ответ:**

```html
<ng-template [ngIf]="show">
  <div>Текст</div>
</ng-template>
```

**Подробнее:** [Конспект §3.3](5_5-templating-konspekt.md#s3-3) · [← вопрос](5_5-templating-voprosy.md#q-11)

<a id="a-12"></a>

### 12. `then option 1`

**Ответ:** имя шаблона с пробелом: `option 1` вместо `option1`. Микросинтаксис не разберёт выражение — ошибка компиляции. Правильно: `then option1 else option2`. Или проще: `@if (show) { Да } @else { Нет }`.

**Подробнее:** [Конспект §3.3](5_5-templating-konspekt.md#s3-3) · [П-2](5_5-templating-popravki.md#p-2) · [← вопрос](5_5-templating-voprosy.md#q-12)

<a id="a-13"></a>

### 13. `'gree'`

**Ответ:** «Другой»: `'green' !== 'gree'`, поэтому совпадёт только `*ngSwitchDefault`. Ошибки не будет — такую опечатку легко пропустить. Помогает тип значения (`'red' | 'green'`) и строгая проверка шаблонов.

**Подробнее:** [Конспект §3.5](5_5-templating-konspekt.md#s3-5) · [П-3](5_5-templating-popravki.md#p-3) · [← вопрос](5_5-templating-voprosy.md#q-13)

<a id="a-14"></a>

### 14. `*ngFor` не работает

**Ответ:** standalone-компонент сам перечисляет в `imports` директивы своего шаблона, а `NgFor` не импортирован. Исправить: добавить `imports: [NgFor]` (или `[CommonModule]`) — либо переписать на `@for`, которому импорт не нужен.

**Подробнее:** [Конспект §3.6](5_5-templating-konspekt.md#s3-6) · [П-7](5_5-templating-popravki.md#p-7) · [← вопрос](5_5-templating-voprosy.md#q-14)

<a id="a-15"></a>

### 15. Перевод на новый синтаксис

**Ответ:**

```html
<ul>
  @for (g of groups; track g.id) {
    <li>{{ $index + 1 }}. {{ g.name }}</li>
  } @empty {
    <li>Групп нет</li>
  }
</ul>
```

**Пояснение:** `*ngIf ... else` + `<ng-template>` существовали только ради пустого списка — их заменяет `@empty`; `let i = index` → `$index`; добавлен обязательный `track`.

**Подробнее:** [Конспект §3.6](5_5-templating-konspekt.md#s3-6) · [Пример 4](5_5-templating-primery.md#ex-4) · [← вопрос](5_5-templating-voprosy.md#q-15)

## D. Привязки

<a id="a-16"></a>

### 16. Четыре привязки

**Ответ:**

- `{{ }}` — интерполяция: из класса в текст;
- `[prop]` — привязка свойства: из класса в свойство элемента;
- `(event)` — привязка события: из шаблона в метод класса;
- `[(ngModel)]` — двусторонняя: в обе стороны.

**Подробнее:** [Конспект §4](5_5-templating-konspekt.md#s4) · [← вопрос](5_5-templating-voprosy.md#q-16)

<a id="a-17"></a>

### 17. Интерполяция или привязка свойства

**Ответ:** A активна: `[disabled]="false"` передаёт булево `false`. B **заблокирована**: интерполяция всегда даёт строку, `"false"` — непустая строка, то есть истина.

**Подробнее:** [Конспект §4.2](5_5-templating-konspekt.md#s4-2) · [← вопрос](5_5-templating-voprosy.md#q-17)

<a id="a-18"></a>

### 18. `[(ngModel)]`

**Ответ:** в `[ngModel]="name" (ngModelChange)="name = $event"`. Нужен `FormsModule` в `imports` компонента. «Банан в коробке» — из-за вида скобок `[( )]`: квадратные (данные в шаблон) снаружи, круглые (событие из шаблона) внутри.

**Подробнее:** [Конспект §4.4](5_5-templating-konspekt.md#s4-4) · [П-4](5_5-templating-popravki.md#p-4) · [← вопрос](5_5-templating-voprosy.md#q-18)

## E. Атрибутные директивы

<a id="a-19"></a>

### 19. `ngClass` и `[class]`

**Ответ:** `<li [class.own]="isOwn">`. Встроенная привязка не требует импорта `NgClass`, короче для одного класса и рекомендуется руководством Angular. Для нескольких классов тоже можно без директивы: `[class]="{ own: isOwn, unread: !read }"`.

**Подробнее:** [Конспект §5](5_5-templating-konspekt.md#s5) · [П-4](5_5-templating-popravki.md#p-4) · [← вопрос](5_5-templating-voprosy.md#q-19)

<a id="a-20"></a>

### 20. Создание директивы

**Ответ:** `ng generate directive highlight` (коротко `ng g d highlight`). Селектор — `[appHighlight]` (CLI добавляет префикс `app`). В Angular 20+ — файл `highlight.ts`, класс `Highlight`; суффикс можно вернуть флагом `--type=directive`.

**Подробнее:** [Конспект §6](5_5-templating-konspekt.md#s6) · [П-5](5_5-templating-popravki.md#p-5) · [← вопрос](5_5-templating-voprosy.md#q-20)

<a id="a-21"></a>

### 21. Директива молчит

**Ответ:** директива не добавлена в `imports` компонента, в шаблоне которого используется. Тогда Angular считает `appHighlight` обычным HTML-атрибутом и ничего не сообщает.

**Подробнее:** [П-5](5_5-templating-popravki.md#p-5) · [Пример 3](5_5-templating-primery.md#ex-3) · [← вопрос](5_5-templating-voprosy.md#q-21)

<a id="a-22"></a>

### 22. Автофокус

**Ответ:** в конструкторе элемент ещё не вставлен в DOM и не готов к фокусу. `ngAfterViewInit` вызывается после отрисовки — элемент на странице, и `focus()` сработает.

**Подробнее:** [Пример 3](5_5-templating-primery.md#ex-3) · [5_1 §3.5 хуки жизненного цикла](5_1-data-persistence-konspekt.md#s3-5) · [← вопрос](5_5-templating-voprosy.md#q-22)

## F. Шаблонные переменные

<a id="a-23"></a>

### 23. Что лежит в переменной

**Ответ:** шаблонная переменная — имя, которое даётся элементу через `#`, чтобы ссылаться на него в шаблоне. На `<input>` — сам DOM-элемент (`nameInput.value`); на компоненте — экземпляр компонента; на `<ng-template>` — сам шаблон.

**Подробнее:** [Конспект §7](5_5-templating-konspekt.md#s7) · [← вопрос](5_5-templating-voprosy.md#q-23)

<a id="a-24"></a>

### 24. Область видимости

**Ответ:** нет. Переменная, объявленная внутри `@for`, видна только внутри своего повторения; снаружи блока `nameInput` не существует — ошибка компиляции. Если нужны значения всех полей, их хранят в данных (например, в массиве или сигнале), а не в шаблонных переменных.

**Подробнее:** [Конспект §7](5_5-templating-konspekt.md#s7) · [П-6](5_5-templating-popravki.md#p-6) · [Пример 2](5_5-templating-primery.md#ex-2) · [← вопрос](5_5-templating-voprosy.md#q-24)
