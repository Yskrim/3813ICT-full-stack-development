## П-1. Ссылка на документацию и кавычки в коде 🔵

### Как в материале

Для пространств имён дана цитата из документации со ссылкой `https://socket.io/docs/rooms-and-namespaces/#Default-room`. Показаны создание пространства имён `io.of(‘/new-namespace’)` и отправка в комнату `socket.to(roomid).emit(“server message”,”message is:”+message)`.

### Пример из материала

```js
const nsp = io.of(‘/new-namespace’);

socket.to(roomid).emit(“server message”,”message is:”+message);
```

### В чём несоответствие

1. **Ссылка устарела.** Раньше пространства имён и комнаты описывались на одной странице `rooms-and-namespaces`; в документации v4 это две страницы: [Namespaces](https://socket.io/docs/v4/namespaces/) и [Rooms](https://socket.io/docs/v4/rooms/). Старый адрес не ведёт на актуальное описание.
2. **Типографские кавычки** (`‘ ’`, `“ ”`) в коде — синтаксическая ошибка при копировании.
3. Склейка строки `"message is:"+message` работает, но шаблонная строка читается проще.

### Как правильно

Актуальные ссылки v4 и обычные кавычки.

### Пример

```js
const nsp = io.of('/new-namespace');

nsp.on('connection', (socket) => {
  socket.on('message', (roomId, message) => {
    socket.to(roomId).emit('server message', `message is: ${message}`);
  });
});
```

**Источник:** [Socket.IO — Namespaces](https://socket.io/docs/v4/namespaces/) · [Socket.IO — Rooms](https://socket.io/docs/v4/rooms/)

## П-2. Личная комната, выход при отключении, `socket.id` 🟡

### Как в материале

Сказано, что у каждого сокета есть случайный уникальный идентификатор `socket.id`, который создаётся при подключении и используется, чтобы присоединить сокет к комнате или отправить сообщение конкретному сокету. Вход и выход из комнат выполняются на сервере. Цитата со ссылкой на раздел «Default room» есть, но само понятие не объяснено.

### Пример из материала

Кода нет.

### В чём несоответствие

Не сказаны три вещи, которые прямо влияют на код:

1. **Личная комната.** Каждый сокет **автоматически** входит в комнату с именем своего `socket.id`. Поэтому «отправить конкретному сокету» — это `io.to(socketId).emit(...)`, та же рассылка в комнату. Проверено: после `join('room1')` у сокета в `socket.rooms` две комнаты — своя и `room1`.
2. **Выход при отключении.** При отключении сокет **сам** покидает все комнаты; вручную вызывать `leave` в `disconnect` не нужно. Проверено: в комнате был 1 сокет, после отключения — 0.
3. **`socket.id` непостоянен.** Он создаётся заново при каждом подключении, в том числе после обрыва связи или перезагрузки страницы. Хранить его как идентификатор пользователя (например, в базе или в объекте «кто в сети») ненадёжно. Документация рекомендует для сообщений конкретному пользователю комнату по **id пользователя** — туда войдут все его вкладки и устройства.

### Как правильно

Использовать личную комнату для одного сокета, комнату `user:<id>` для пользователя, и не заниматься очисткой комнат при отключении.

### Пример

```js
io.on('connection', (socket) => {
  // userId в реальном приложении определяют по сессии; здесь — из данных подключения (учебно)
  const userId = socket.handshake.auth.userId;
  socket.join(`user:${userId}`);                   // все вкладки пользователя в одной комнате

  console.log([...socket.rooms]);                  // [ '<socket.id>', 'user:2' ]

  // Одному сокету — через его личную комнату
  io.to(socket.id).emit('message', 'Только этой вкладке');

  // Пользователю — во все его вкладки
  io.to(`user:${userId}`).emit('notification', 'У вас новое приглашение');

  socket.on('disconnect', () => {
    // leave() не нужен — сокет уже покинул все комнаты
  });
});

// Клиент: передать данные при подключении
// const socket = io('http://localhost:3000', { auth: { userId: 2 } });
```

## П-3. `socket.to(room).emit` 🟡

### Как в материале

Показано, как отправить сообщение в комнату: `socket.to(roomid).emit(...)`. Сказано, что после входа в комнату сообщения, проходящие через сервер, отправляются только в эту комнату.

### Пример из материала

```js
socket.to(roomid).emit(“server message”,”message is:”+message);
```

### В чём несоответствие

Не сказано главное свойство этого вызова: `socket.to(room).emit` отправляет всем участникам комнаты, **кроме самого отправителя**. Если так рассылать сообщения чата, отправитель не увидит своё сообщение, пришедшее с сервера. Чтобы получили **все** участники, включая отправителя, используют `io.to(room).emit`.

Проверено тремя клиентами (A и B в комнате `r1`, C — нет, событие инициировал A):

```
socket.to('r1').emit → B
io.to('r1').emit     → A, B
```

### Как правильно

`socket.to(room)` — «остальным в комнате» (например, «anna печатает…»); `io.to(room)` — «всем в комнате» (сообщения чата).

### Пример

```js
io.on('connection', (socket) => {
  socket.on('message', ({ room, text }) => {
    io.to(room).emit('message', text);            // сообщение канала — всем, включая отправителя
  });

  socket.on('typing', ({ room, name }) => {
    socket.to(room).emit('typing', name);         // «печатает…» — всем, кроме печатающего
  });
});
```

**Источник:** [Socket.IO — Rooms](https://socket.io/docs/v4/rooms/) («every socket in the room excluding the sender will get the event») · [Socket.IO — Emit cheatsheet](https://socket.io/docs/v4/emit-cheatsheet/)

## П-4. «Сервер хранит запись о комнатах» 🟡

### Как в материале

Описан рабочий процесс: клиент подключается; просит войти в комнату, передавая её имя; сервер хранит запись о том, какие `socket.id` вошли в какую комнату; клиент отправляет сообщение; сервер отправляет его каждому `socket.id`, записанному в комнате; клиент показывает сообщение. Также сказано, что сообщения, проходящие через сервер, сначала должны проверить, в какой они комнате.

### Пример из материала

Кода нет (схема из шести шагов).

### В чём несоответствие

Схема создаёт впечатление, что учёт участников комнат и рассылку по списку `socket.id` нужно писать самому. На деле это делает Socket.IO: **адаптер** хранит, какие сокеты в каких комнатах, а `io.to(room).emit` сам рассылает всем участникам. Документация прямо предупреждает, что внутренние структуры адаптера нельзя менять напрямую — только через `socket.join()` и `socket.leave()`. Собственный параллельный список участников легко рассинхронизировать: например, забыть удалить сокет при отключении.

Собственная работа сервера другая:

1. **проверить права** — может ли этот пользователь войти в эту комнату и писать в неё;
2. **знать текущую комнату сокета**, если сообщение приходит без указания комнаты;
3. при необходимости — хранить **данные приложения** (например, историю сообщений или список участников группы для интерфейса), а не список сокетов для рассылки.

### Как правильно

Членство — через `join`/`leave`, рассылка — через `io.to(room)`, собственный код — проверка прав.

### Пример

```js
io.on('connection', (socket) => {
  socket.on('join-channel', async (channelId, ack) => {
    const allowed = await canJoin(socket.handshake.auth.userId, channelId);   // проверка прав — наша работа
    if (!allowed) return ack({ ok: false, error: 'Forbidden' });
    socket.join(`channel:${channelId}`);                                       // учёт — работа Socket.IO
    ack({ ok: true });
  });

  socket.on('message', ({ channelId, text }) => {
    if (!socket.rooms.has(`channel:${channelId}`)) return;   // писать можно только в свой канал
    io.to(`channel:${channelId}`).emit('message', text);     // рассылка — работа Socket.IO
  });
});

// Сколько сокетов в комнате — для отладки (только чтение):
// io.of('/').adapter.rooms.get('channel:5')?.size

// ❌ Не нужно: свой объект { 'channel:5': ['socketId1', 'socketId2'] } для рассылки
```
