# 4 — Каналы через комнаты

**Темы:** пространства имён и комнаты (6_6)
**Место:** четвёртое из четырёх, рабочий кусок Phase 2
**Время:** 60 минут
**Опирается на:** [3 — Чат на Socket.IO](../03-socket-chat/README.md)
**Дальше:** пришли решения в чат — разберём и перейдём к Phase 2

## Задача

Чат из задания 3 рассылает каждое сообщение всем подключённым. В Phase 2 у чата есть группы и каналы, и сообщение из `#homework` не должно появляться у тех, кто сидит в `#random`. Нужно отправлять сообщения не всем, а группе сокетов. В Socket.IO такие группы называются **комнатами**.

Комнаты — чисто серверное понятие. Клиент не может войти в комнату сам: он только **просит** («хочу в канал homework»), а сервер решает и выполняет. Сервер же знает, в какой комнате сейчас сокет, поэтому сообщения можно отправлять без указания канала — сервер разошлёт их в текущую комнату отправителя.

Заодно ты используешь разницу между двумя рассылками в комнату. `io.to(room)` отправляет всем в комнате, включая отправителя, — это для сообщений. `socket.to(room)` отправляет всем, кроме отправителя, — это для уведомлений вроде «кто-то вошёл» или «кто-то печатает…».

## Зачем это задание

Каналы Phase 2 будут устроены именно так. А правило «клиент просит — сервер проверяет и решает» — основа безопасности всего чата.

## Что проверяет

1. Ты входишь в комнату и выходишь из неё на сервере по просьбе клиента.
2. Ты помнишь текущую комнату сокета и меняешь её при переключении канала.
3. Ты выбираешь между `io.to(room)` и `socket.to(room)` по смыслу.
4. Ты понимаешь, что при отключении комнаты покидаются сами.

## Старт

Каналы — фиксированный список: `general`, `random`, `homework`. Продолжай в файлах задания 3.

## Что сделать

**Часть А — сервер**

1. Событие `join-channel` с именем канала: проверить, что канал из списка; выйти из прежней комнаты сокета; войти в `channel:<имя>`; остальным участникам нового канала — системное событие `system` «кто-то вошёл».
2. `message` рассылается **только в текущую комнату** отправителя, включая его самого. Сокет без канала сообщения отправлять не может.
3. Событие `typing`: всем в комнате, кроме печатающего.
4. При отключении ничего из комнат вручную не удалять.

**Часть Б — клиент**

1. В `SocketService`: `joinChannel(name)`, `system$()` и `typing$()` — по образцу `messages$()` из задания 3 (с функцией очистки).
2. На странице чата — три кнопки каналов; текущий подсвечен. При переключении — просьба серверу и очистка ленты.
3. Системные сообщения показываются в ленте иначе, чем обычные (например, серым курсивом).
4. Пока пользователь печатает, клиент отправляет `typing`, но не чаще раза в секунду. У остальных появляется «кто-то печатает…» и исчезает через 2 секунды без новых событий.

**Часть В — проверка**

Три вкладки: две в `general`, одна в `random`. Запиши в `observations.md`:

1. Сообщение из `general` — у кого появилось?
2. Кто видит системное сообщение, когда третья вкладка переходит в `general`? Видит ли его она сама?
3. Кто видит «печатает…»?
4. Отправь из консоли браузера `join-channel` с именем `admin` — что сделал сервер?

**Бонус**

Сделай так, чтобы `join-channel` отвечал подтверждением (acknowledgement) с числом участников канала, и покажи его рядом с названием.

## Критерии готовности

- [ ] Сообщения видят только участники канала, включая отправителя
- [ ] «Вошёл» и «печатает…» не показываются самому инициатору
- [ ] Неизвестный канал сервер отклоняет
- [ ] Переключение канала не оставляет сокет в прежней комнате
- [ ] Ты можешь ответить: почему клиент не может войти в комнату сам и почему это хорошо?
- [ ] Ты можешь ответить: почему для сообщений нужен `io.to`, а для «печатает…» — `socket.to`?
- [ ] Ты можешь ответить: почему нельзя хранить `socket.id` как идентификатор пользователя?

## Типичные ловушки

- Сообщение рассылается через `socket.to(room)` — отправитель не видит своё сообщение.
- Вход в новый канал без выхода из прежнего — сокет получает сообщения двух каналов.
- Имя канала от клиента используется без проверки.
- Таймер «печатает…» не сбрасывается при новом событии — надпись мигает.
