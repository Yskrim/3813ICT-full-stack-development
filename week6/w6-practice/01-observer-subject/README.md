# 1 — Observer и Subject руками

**Темы:** реактивное программирование и Observables (6_0, 6_1)
**Место:** первое из четырёх, базовый концепт
**Время:** 40 минут
**Опирается на:** [0 — Подготовка](../00-setup/README.md)
**Дальше:** [2 — Promise, async и fetch](../02-promises/README.md)

## Задача

В заданиях 3 и 4 сообщения из сокета будут приходить потоком, и компонент будет на него подписываться. Чтобы этот код не был магией, начнём с механизма, который под ним лежит. Паттерн Observer очень простой: субъект хранит список наблюдателей и вызывает их, когда что-то происходит. Лучший способ это прочувствовать — один раз написать его самому.

Потом ты сравнишь свою версию с готовой из RxJS и проверишь на опытах две вещи, на которых часто ошибаются. Первая: обычный Observable и Subject по-разному ведут себя с несколькими подписчиками. Вторая: «отписать наблюдателя» и «закрыть Subject» — разные операции.

## Зачем это задание

От того, понимаешь ли ты разницу между подпиской, отпиской и завершением потока, зависит, будут ли в чате дублироваться сообщения. Это ровно та ошибка, которую мы найдём в задании 3.

## Что проверяет

1. Ты можешь реализовать паттерн Observer с подпиской и отпиской.
2. Ты используешь интерфейс, чтобы субъект работал с разными наблюдателями.
3. Ты различаешь unicast (обычный Observable) и multicast (Subject).
4. Ты отписываешь через `Subscription`, а не через `subject.unsubscribe(...)`.

## Старт

Создай файл `src/app/pages/lab/observer-lab.ts`. Опыты запускай из `LabComponent` — по кнопке на опыт, вывод в консоль. Наблюдения записывай в `observations.md` в папке этого задания.

## Что сделать

**Часть А — свой Subject (строгий TypeScript, без `any`)**

1. Интерфейс `Observer` с методом `changed(value: string): void`.
2. Класс `Subject` хранит значение и список наблюдателей. `subscribe(observer)` добавляет наблюдателя и **возвращает функцию отписки**. `changeValue(value)` меняет значение и уведомляет всех.
3. Три разных наблюдателя: один пишет в консоль, другой считает вызовы, третий — обычный объект без класса.
4. Сценарий: подпиши всех троих, измени значение, отпиши одного, снова измени. Проверь, что отписанный больше ничего не получил.

**Часть Б — RxJS: unicast и multicast**

Сначала предскажи вывод, потом запусти:

```ts
import { Observable, Subject, BehaviorSubject } from 'rxjs';

let runs = 0;
const cold$ = new Observable<number>((s) => { runs++; s.next(runs); });
cold$.subscribe((v) => console.log('cold A', v));
cold$.subscribe((v) => console.log('cold B', v));

const hot = new Subject<number>();
hot.subscribe((v) => console.log('hot A', v));
hot.subscribe((v) => console.log('hot B', v));
hot.next(Math.random());

const current = new BehaviorSubject('general');
current.next('random');
current.subscribe((v) => console.log('поздний подписчик видит', v));
```

**Часть В — отписка и завершение**

1. Подпиши на `Subject<number>` двух подписчиков, сохрани `Subscription` первого. Отправь 5, отпиши первого, отправь 9, вызови `complete()`, отправь 11. Кто что получил?
2. Напиши `subject.unsubscribe(observer)` и прочитай ошибку компилятора. Затем вызови `subject.unsubscribe()` без аргументов и после этого `next(1)`. Что произошло?

## Типичные ловушки

- `observers = []` без типа — в строгом режиме это `never[]`.
- Отписка через `splice` по индексу, найденному заранее: после другой отписки индекс устаревает.
- Путаница `subject.unsubscribe()` с `subscription.unsubscribe()`.
