# Week 9. Практика перед Workshop

**Цель:** спокойно потренировать каждый слой отдельно, прежде чем собирать всё в Workshop 9.  
**Связанные материалы:** [конспект 9.1 — MongoDB из Node.js](../materials/9_1-node-mongodb-konspekt.md) · [конспект 9.2 — Express и Angular](../materials/9_2-mongodb-express-angular-konspekt.md) · [конспект 9.3 — CRUD-приложение](../materials/9_3-product-crud-app-konspekt.md) · [Workshop 9](../Workshop/workshop9-konspekt.md)

Идём от небольшого скрипта к полному потоку данных. В каждом задании сначала добейся, чтобы работал текущий слой, и только потом переходи к следующему. Используй отдельную учебную базу, например `week9_practice`; не запускай очистку коллекции для баз с нужными данными.

Для всех заданий используй товар с полями `id` (число), `name` (строка), `description` (строка), `price` (неотрицательное число) и `units` (целое число не меньше нуля). Помни: MongoDB автоматически добавляет `_id`, а прикладной `id` — отдельное поле.

## Задание 1. CRUD в небольшом Node.js-скрипте

Начнём с базы без Express и Angular. Так проще понять, что именно возвращает драйвер и как данные меняются в коллекции.

1. Подключись к MongoDB через один `MongoClient`.
2. Выбери базу `week9_practice` и коллекцию `products`.
3. Создай один товар через `insertOne` и сохрани `insertedId`.
4. Найди документ по `_id`, затем выведи все документы через `find({}).toArray()`.
5. Измени `units` через `updateOne` и проверь `matchedCount` и `modifiedCount`.
6. Удали созданный документ через `deleteOne` и проверь `deletedCount`.
7. Закрой клиент в `finally`, чтобы скрипт корректно завершался и при ошибке.

**Контрольная точка:** в терминале видно вставленный товар, обновлённое значение и подтверждение удаления. После завершения документа больше нет в коллекции.

**Подсказка:** не ищи по `_id` как по обычной строке, если он пришёл из пользовательского ввода: проверь формат и преобразуй его в `ObjectId`. Для `insertedId`, который вернул драйвер, преобразование не требуется.

## Задание 2. Тот же каталог через Express API

Теперь база уже знакома, поэтому добавим сетевую границу. Express должен принимать запросы, проверять входные данные и возвращать понятный HTTP-ответ.

1. Подключи `express.json()` и переиспользуй один подключённый `MongoClient`.
2. Добавь `GET /api/products`, возвращающий массив товаров.
3. Добавь `POST /api/products`, который проверяет поля и создаёт документ. При успехе верни `201`.
4. Добавь `PATCH /api/products/:id`. Проверь формат `_id`, обновляй только разрешённые поля и возвращай `404`, если товар не найден.
5. Добавь `DELETE /api/products/:id`. Если документ удалён, верни `204`; если такого документа нет — `404`.
6. Создай уникальный индекс `{ id: 1 }`. Если MongoDB сообщает о повторяющемся `id`, верни `409`.
7. Обработай неожиданные ошибки централизованно, не отправляя клиенту внутренние детали подключения к базе.

**Контрольная точка:** каждый маршрут можно отдельно вызвать из браузера/API-клиента. Проверь и успешные ответы, и случаи «неверный ID», «не найдено», «повторный id».

**Подсказка:** проверка `id` запросом к базе перед вставкой полезна для раннего сообщения, но сама не гарантирует уникальность при двух одновременных запросах. Гарантию обеспечивает индекс.

## Задание 3. Подключи Angular к API

Последний шаг соединяет интерфейс с уже работающим сервером. Здесь пригодятся формы из прошлых тем и Observable, с которыми мы познакомились в Week 6.

1. Опиши интерфейс `Product` с `_id`, `id`, `name`, `description`, `price` и `units`.
2. Создай `ProductService` с методами `list`, `add`, `update` и `remove`; пусть они возвращают Observable из `HttpClient`.
3. Подключи `HttpClient` в конфигурации своего Angular-проекта. Для формы с `[(ngModel)]` подключи `FormsModule`.
4. Сделай компонент списка: загрузи товары при открытии и покажи имя, цену и количество.
5. Добавь форму создания и действие удаления. После успешного ответа обнови список или повторно загрузи его.
6. Добавь редактирование: передавай `_id` в URL и загружай актуальную запись с сервера, затем отправляй разрешённые поля в `PATCH`.
7. Покажи пользователю состояние загрузки и понятное сообщение, если API вернул ошибку.

**Контрольная точка:** создай товар, обнови страницу и убедись, что товар загрузился заново с сервера; затем измени и удали его через интерфейс. Проверь также реакцию формы на невалидные данные.

**Подсказка:** `HttpClient` возвращает Observable; запрос начнётся при подписке. Не обновляй экран до успешного ответа так, будто запись уже точно сохранилась.
