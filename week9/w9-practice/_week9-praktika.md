## Задание 1. Найди, почему код не работает

Сначала — чтение кода. Для каждого фрагмента **предскажи**, что произойдёт при запуске с драйвером `mongodb` 7.x и Express 5, назови причину одной фразой и перепиши фрагмент правильно.

```js
// 1
main().then(console.log('main...')).finally(() => client.close());

// 2
collection.insertMany(docs, function (err, result) { console.log('done'); client.close(); });

// 3
col.find({}).toArray().then(function (err, result) { if (err) throw err; console.log(result); });

// 4
app.get('/api/prodcount', (req, res) => {
  if (!req.body) return res.sendStatus(400);
  col.countDocuments({}).then((count) => res.json({ count }));
});

// 5
const n = await col.countDocuments({ id: p.id });
if (n === 0) await col.insertOne(p);

// 6 — сервер: app.post('/productDelete', ...)   клиент:
this.http.delete(this.url + 'productDelete', prod).subscribe();

// 7
exports.update = async (req, res) => {
  res.send(await col.updateMany(req.body.query, { $set: req.body.update }));
};
```

**Готово, если:** для всех семи фрагментов есть предсказание, причина и исправленный вариант. Для фрагмента 5 ты можешь объяснить, почему даже без ошибок синтаксиса он не защищает от дубликатов, а для 7 — что может сделать чужой клиент.

## Задание 2. Собери сервер магазина

Теперь напиши сервер, на который потом встанет Angular. Товар: `id` (целое число, номер для пользователя), `name`, `description`, `price`, `units`.

**Подготовка**

1. Новый Node-проект с `express` и `mongodb`. Проверь версию Node.js — драйверу 7.x нужна 20.19 или новее.
2. Модуль `db.js`: **одно** подключение на весь сервер, функции `connect` и `getDb`. Express начинает слушать порт только после успешного подключения; если `mongod` не запущен — понятное сообщение и выход.
3. При запуске создай уникальный индекс по `id`.

**Маршруты** (один роутер на `/api/products`)

1. `GET /count` — количество товаров.
2. `GET /check-id/:id` — `{ available, nextId }`, где `nextId` — следующий свободный номер.
3. `GET /` — список, отсортированный по `id`.
4. `GET /:id` — один товар по `_id`.
5. `POST /` — создать; дубликат `id` → `409`.
6. `PUT /:id` — изменить `name`, `description`, `price`, `units`; поле `id` менять нельзя.
7. `DELETE /:id` — удалить один товар.

Правила для всех маршрутов: сервер сам собирает документ из разрешённых полей и проверяет типы; фильтр строит сервер — по `_id` из адреса; неверный `_id` → `400`, документа нет → `404`; соединение с базой в маршрутах не открывается и не закрывается.

**Проверка**

Прежде чем запускать, **предскажи**, что ответит `GET /api/products/count`, если объявить маршрут `/count` ниже `/:id`. Проверь — и верни правильный порядок. Затем проверь все маршруты (curl, Postman или скрипт) и запиши коды ответов, в том числе для повторного добавления того же `id`, неверного `_id` и повторного удаления.

**Готово, если:**

- сервер не запускается без базы и сообщает об этом, а с базой — стартует после подключения;
- дубликат отклоняет уникальный индекс, а не предварительный подсчёт, и клиент получает `409`;
- в теле `PUT` можно прислать `id`, но он не изменится — и ты можешь показать, в какой строке кода это обеспечено;
- все семь маршрутов отвечают ожидаемыми кодами, результаты записаны.

## Задание 3. Подключи Angular

Теперь клиент. Нужны четыре экрана: главная со счётчиком, список, добавление, редактирование. Если у тебя есть Angular-проект из прошлых недель, работай в нём; иначе создай новый и настрой прокси `/api` на сервер (как в [5_3](../week5/5_3-node-hosting-konspekt.md#s2-5)).

1. **Сервис.** Типизированные методы под семь маршрутов; каждый возвращает Observable; один базовый адрес `/api/products`.
2. **Главная.** Количество товаров с тремя состояниями: загрузка, число, ошибка.
3. **Список.** Таблица с `@for`; «Удалить» с подтверждением убирает строку **без** повторной загрузки всего списка; «Изменить» — ссылка с `_id` в адресе.
4. **Добавление.** Форма с `ngSubmit`. При вводе ID показывается подсказка о занятом номере — но не чаще одного запроса после паузы в наборе, и прежний запрос отменяется новым. Ответы `400` и `409` сервера показываются под формой.
5. **Редактирование.** Страница `/update/:id` загружает товар с сервера (работает и после F5), поле ID только для чтения, после сохранения — переход на список.
6. **По желанию:** плавное появление и исчезновение подсказки через `animate.enter` / `animate.leave` и CSS.

Перед пунктом 4 **предскажи**, сколько запросов уйдёт при быстром вводе «123» без паузы и отмены, а потом проверь во вкладке Network — с ними и без них.

**Готово, если:**

- ни в сервисе, ни в компонентах нет `any`, а поля классов имеют начальные значения;
- удаление, добавление и редактирование работают против сервера из задания 2, а ошибки видны пользователю;
- при быстром вводе ID в Network один запрос, а не по одному на символ;
- страница редактирования открывается по прямой ссылке и после F5.
