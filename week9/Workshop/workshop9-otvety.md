# Workshop 9. Ответы и пояснения

**Связанные файлы:** [конспект](workshop9-konspekt.md) · [план и примеры](workshop9-primery.md) · [вопросы](workshop9-voprosy.md) · [заметки](workshop9-popravki.md)

1. Create, Read, Update, Delete: добавить, прочитать, изменить и удалить.
2. `id` — прикладной номер товара, который задаёт приложение; `_id` — идентификатор документа, созданный MongoDB. Удобно адресовать документ через `_id`, а числовой `id` хранить только если он нужен по заданию.
3. Если одна операция сломана, её проще локализовать до того, как добавились HTTP, JSON и интерфейс. Каждый слой становится понятной контрольной точкой.
4. Сервер должен убедиться, что цена — конечное неотрицательное число, а `units` — целое неотрицательное число. Также проверь строки и обязательные поля.
5. Установить уникальный индекс по `{ id: 1 }` и преобразовывать ошибку duplicate key в понятный HTTP `409`. Предварительный поиск помогает сообщить о конфликте, но не заменяет индекс.
6. Например, `PATCH /api/products/:id`: в URL передаём MongoDB `_id`, в теле — разрешённые поля, которые хотим изменить. Сначала проверь формат ID и данные.
7. Состояние только в компоненте исчезнет при перезагрузке. Повторный GET из API подтверждает, что данные действительно записаны в постоянное хранилище.
8. Покажи открытие списка, добавление нового товара, изменение существующего и удаление; объясняй ответы сервера и показывай, что после перезагрузки состояние сохраняется.

Полезное правило: отлаживай приложение снаружи внутрь — сначала подтвердить MongoDB операции, затем API, затем подключать Angular.
