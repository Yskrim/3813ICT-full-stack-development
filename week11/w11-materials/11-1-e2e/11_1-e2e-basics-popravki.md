## П-1. «Предпочтительно ручное», «после системного» 🔵

### Как в материале

Слайды 2 и 4: сквозное тестирование обычно выполняется после функционального и системного; в сравнительной таблице сказано, что сквозное тестирование проверяет внешние интерфейсы, которые сложно автоматизировать, поэтому предпочтительно ручное тестирование.

### В чём несоответствие

Для веб-приложений это устарело. Сквозные тесты автоматизируют инструментами, которые управляют настоящим браузером, — Cypress, Playwright, WebdriverIO; сам курс переходит к ним в 11_2 и 11_3, а Angular подключает их через `ng e2e`. Автоматические сквозные тесты запускают не одним этапом «после системного тестирования», а постоянно — при каждом изменении кода (в CI), потому что так регрессии находят сразу. Ручное тестирование остаётся для исследовательских проверок и того, что трудно формализовать.

Внешние системы, которые нельзя вызывать из тестов (платёжный шлюз, чужой API), в автоматических тестах заменяют подменой сетевого ответа — например, `cy.intercept` в Cypress.

### Как правильно

Главные сценарии — автоматические сквозные тесты на каждом изменении; ручные проверки — дополнение.

### Пример

```ts
// Cypress: внешний сервис подменён, сценарий автоматический
cy.intercept('GET', 'https://api.example-payments.com/**', { statusCode: 200, body: { ok: true } });
cy.visit('/checkout');
cy.get('[data-cy=pay]').click();
cy.contains('Оплата прошла');
```

**Источник:** [Angular — End to End Testing (ng e2e)](https://angular.dev/tools/cli/end-to-end) · [Cypress — cy.intercept](https://docs.cypress.io/api/commands/intercept)

## П-2. «Реальные рабочие данные» 🟡

### Как в материале

Слайд 2: сквозное тестирование использует реальные данные, похожие на рабочие, и тестовую среду, имитирующую реальные условия.

### В чём несоответствие

Среда действительно должна быть похожа на рабочую (те же версии, та же конфигурация). Но данные в ней должны быть **тестовыми**: реальные данные пользователей в тестах нарушают приватность, тесты их меняют и портят, а результат зависит от того, что в данных сейчас. Тесты готовят свои данные перед запуском (seed) и убирают их после — как в интеграционных тестах ([10_2 П-6](10_2-mocha-popravki.md#p-6)). Пример из 11_3 курса, где в тесте вводятся реальный на вид адрес преподавателя и пароль, показывает, к чему приводит обратное.

### Как правильно

Отдельная тестовая среда и база; тестовые пользователи создаются перед тестами.

### Пример

```js
// server/seed-e2e.js — тестовые пользователи перед сквозными тестами (только в тестовой среде)
await getDb().collection('users').deleteMany({});
await getDb().collection('users').insertMany([
  { _id: 1, username: 'e2e-super', pwd: 'test-123', role: 'superadmin' },
  { _id: 2, username: 'e2e-user', pwd: 'test-123', role: 'user' },
]);
```

**Источник:** [Cypress — Best Practices: Organizing tests, logging in, controlling state](https://docs.cypress.io/app/core-concepts/best-practices)
