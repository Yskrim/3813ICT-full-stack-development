## A. Cypress

<a id="a-1"></a>

### 1. Чем Cypress отличается от Protractor

**Ответ:** Cypress не использует WebDriver — тесты выполняются прямо в браузере рядом с приложением, поэтому он видит DOM, сеть и хранилища напрямую. И он сам ждёт элементы и проверки (очередь команд с повторением) — без `await` и control flow.

**Подробнее:** [Конспект §1](11_3-cypress-konspekt.md#s1) · [11_2 §6](11_2-protractor-konspekt.md#s6) · [← вопрос](11_3-cypress-voprosy.md#q-1)

<a id="a-2"></a>

### 2. Установка и структура

**Ответ:** `ng add @cypress/schematic`. `e2e/` — тесты, `support/` — общий код (свои команды, действия перед каждым тестом), `fixtures/` — тестовые данные JSON. Файлы тестов — `*.cy.ts`.

**Подробнее:** [Конспект §2](11_3-cypress-konspekt.md#s2) · [← вопрос](11_3-cypress-voprosy.md#q-2)

<a id="a-3"></a>

### 3. Синтаксис

**Ответ:** верно «Mocha и Chai». `toEqual` — проверка Jasmine, в Cypress её нет; нужно `expect(title).to.equal('MyApp')` или `cy.title().should('equal', 'MyApp')`.

**Подробнее:** [Конспект §3](11_3-cypress-konspekt.md#s3) · [П-1](11_3-cypress-popravki.md#p-1) · [← вопрос](11_3-cypress-voprosy.md#q-3)

<a id="a-4"></a>

### 4. Очередь команд

**Ответ:** `cy.get` не возвращает элемент — команда ставится в очередь и выполнится позже; с результатом работают через цепочку (`.type`, `.should`, `.then`). Поиск и `should` повторяются автоматически до успеха или таймаута (4 секунды), поэтому задержка ответа сервера не роняет тест.

**Подробнее:** [Конспект §3](11_3-cypress-konspekt.md#s3) · [← вопрос](11_3-cypress-voprosy.md#q-4)

<a id="a-5"></a>

### 5. Запуск

**Ответ:** `run` — без окна (headless), для CI и быстрой проверки; `open` — интерактивное окно с выбором браузера и тестов, перезапуск при изменениях. При `ng e2e`, добавленном схематиком, `ng serve` запускается автоматически; при `npx cypress ...` фронтенд нужно запустить самому.

**Подробнее:** [Конспект §5](11_3-cypress-konspekt.md#s5) · [П-2](11_3-cypress-popravki.md#p-2) · [← вопрос](11_3-cypress-voprosy.md#q-5)

## B. Надёжные тесты

<a id="a-6"></a>

### 6. Зелёный без причины

**Ответ:** тест пройдёт: обработчик не вызовется, `expect` внутри него не выполнится. Правильно — подменить `alert` заглушкой и проверить вызов:

```ts
cy.visit('/login', { onBeforeLoad(win) { cy.stub(win, 'alert').as('alert'); } });
cy.get('[data-cy=submit]').click();
cy.get('@alert').should('have.been.calledOnceWith', 'correct');
```

**Подробнее:** [Конспект §6.2](11_3-cypress-konspekt.md#s6-2) · [П-3](11_3-cypress-popravki.md#p-3) · [← вопрос](11_3-cypress-voprosy.md#q-6)

<a id="a-7"></a>

### 7. Селекторы

**Ответ:** они зависят от порядка элементов и от того, сколько на странице полей и кнопок: новое поле или вторая кнопка ломают тест. Документация Cypress рекомендует атрибуты `data-cy`, которые нужны только тестам.

**Подробнее:** [Конспект §6.2](11_3-cypress-konspekt.md#s6-2) · [П-4](11_3-cypress-popravki.md#p-4) · [← вопрос](11_3-cypress-voprosy.md#q-7)

<a id="a-8"></a>

### 8. Что проверять

**Ответ:** пользователь не видит sessionStorage; проверка привязывает тест к способу хранения — при смене ключа или хранилища тест упадёт, хотя вход работает. Проверять видимое: адрес страницы после входа и имя пользователя на странице.

**Подробнее:** [Конспект §6.2](11_3-cypress-konspekt.md#s6-2) · [11_1 — вопрос 7](11_1-e2e-basics-otvety.md#a-7) · [← вопрос](11_3-cypress-voprosy.md#q-8)

## C. Приёмы

<a id="a-9"></a>

### 9. `cy.intercept`

**Ответ:** `cy.intercept('GET', '/api/groups', { statusCode: 500, body: { error: 'Server error' } }).as('groups')`, затем загрузить страницу, `cy.wait('@groups')` и проверить, что сообщение об ошибке видно. `cy.wait('@alias')` ждёт именно этот запрос, а не угадывает время, — тест не зависит от скорости.

**Подробнее:** [Пример 1](11_3-cypress-primery.md#ex-1) · [← вопрос](11_3-cypress-voprosy.md#q-9)

<a id="a-10"></a>

### 10. Вход в каждом тесте

**Ответ:** это медленно и повторяет одно и то же; если сломается форма входа, упадут все двадцать тестов, и будет трудно понять причину. Cypress предлагает свою команду (`Cypress.Commands.add('login', ...)`), которая входит через API, и `cy.session`, который запоминает состояние после первого входа и восстанавливает его. Форма входа проверяется одним отдельным тестом.

**Подробнее:** [Пример 2](11_3-cypress-primery.md#ex-2) · [← вопрос](11_3-cypress-voprosy.md#q-10)
