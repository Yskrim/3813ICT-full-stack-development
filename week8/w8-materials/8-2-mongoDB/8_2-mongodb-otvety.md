## A. Инструменты и установка

<a id="a-1"></a>

### 1. Кто есть кто

**Ответ:** `mongod` — сервер базы данных: он хранит данные на диске и принимает запросы (порт 27017). `mongosh` — оболочка командной строки для ручной работы с сервером. `mongodb` — драйвер, через который к серверу подключается код на Node.js. Данные хранит только `mongod`.

**Подробнее:** [Конспект §1.2](8_2-mongodb-konspekt.md#s1-2) · [← вопрос](8_2-mongodb-voprosy.md#q-1)

<a id="a-2"></a>

### 2. Установка из материала

**Ответ:** формулы `mongodb` в основном репозитории Homebrew больше нет; корень `/data` на современных macOS защищён от записи; `sudo chown` по системным папкам не нужен; в `id –un` длинное тире. Сейчас:

```bash
brew tap mongodb/brew
brew install mongodb-community@8.0
brew services start mongodb-community@8.0
mongosh
```

Каталог данных и настройки Homebrew создаёт сам.

## B. Базы, коллекции, документы

<a id="a-3"></a>

### 3. Есть ли база

**Ответ:** нет. `use` только переключает оболочку на имя `shop`. База появится на диске при первой записи — вставке документа или создании коллекции; после этого она будет видна в `show dbs`.

**Подробнее:** [Конспект §4.1](8_2-mongodb-konspekt.md#s4-1) · [П-3](8_2-mongodb-popravki.md#p-3) · [← вопрос](8_2-mongodb-voprosy.md#q-3)

<a id="a-4"></a>

### 4. Что показал скриншот

**Ответ:** база не удалена. `dropDatabse` — опечатка, и нет скобок: оболочка восприняла `db.dropDatabse` как обращение к коллекции с таким именем и вывела её полное имя `test.dropDatabse`. Правильно и безопасно: проверить текущую базу командой `db`, затем `db.dropDatabase()` — ответ `{ ok: 1, dropped: 'test' }`.

**Подробнее:** [Конспект §4.2](8_2-mongodb-konspekt.md#s4-2) · [П-4](8_2-mongodb-popravki.md#p-4) · [← вопрос](8_2-mongodb-voprosy.md#q-4)

<a id="a-5"></a>

### 5. `id` и `_id`

**Ответ:** `_id` — обязательный уникальный идентификатор документа; вторая вставка с `_id: 1` завершится ошибкой `E11000 duplicate key error`. `id` — обычное поле без гарантий; второй документ с `id: 7` вставится спокойно, и появятся два «одинаковых» id.

**Пояснение:** свой идентификатор кладут прямо в `_id`, а не в отдельное поле.

**Подробнее:** [Конспект §3](8_2-mongodb-konspekt.md#s3) · [П-6](8_2-mongodb-popravki.md#p-6) · [← вопрос](8_2-mongodb-voprosy.md#q-5)

## C. Чтение

<a id="a-6"></a>

### 6. Проекция

**Ответ:** все документы с полями `_id` и `id`. `_id` включается по умолчанию, хотя его не просили; поля `data` в документах нет — оно молча игнорируется, без ошибки.

**Подробнее:** [Конспект §6.1](8_2-mongodb-konspekt.md#s6-1) · [П-8](8_2-mongodb-popravki.md#p-8) · [← вопрос](8_2-mongodb-voprosy.md#q-6)

<a id="a-7"></a>

### 7. Найди ошибки

**Ответ:**

1. в проекции смешаны включение (`title: 1`) и исключение обычного поля (`stock: 0`) — ошибка сервера;
2. `count` без скобок — это функция, а не вызов, и `count()` к тому же устарел;
3. `sort` принимает объект.

```js
db.books.find({}, { title: 1 })            // или { stock: 0 } — что-то одно
db.books.countDocuments({})
db.books.find().sort({ price: -1 })
```

**Подробнее:** [Конспект §6.1](8_2-mongodb-konspekt.md#s6-1) · [П-11](8_2-mongodb-popravki.md#p-11) · [← вопрос](8_2-mongodb-voprosy.md#q-7)

<a id="a-8"></a>

### 8. Число или строка

**Ответ:** только документ с числом `45`. Операторы сравнения сравнивают значения одного типа: строка `'45'` с числом `40` не сравнивается, и документ не подходит — без ошибки.

**Пояснение:** поэтому цены хранят числами, а данные из форм перед записью приводят к нужному типу.

**Подробнее:** [Конспект §6.3](8_2-mongodb-konspekt.md#s6-3) · [П-9](8_2-mongodb-popravki.md#p-9) · [← вопрос](8_2-mongodb-voprosy.md#q-8)

<a id="a-9"></a>

### 9. Исправь шпаргалку

**Ответ:**

```js
find({ $and: [expr1, expr2] })     // AND — все условия
find({ $or: [expr1, expr2] })      // OR — хотя бы одно
find({ price: { $not: { $gt: 50 } } })   // NOT — внутри условия поля
```

`$not` отрицает оператор конкретного поля и не бывает на верхнем уровне; отрицание нескольких условий — `$nor`.

**Подробнее:** [Конспект §6.4](8_2-mongodb-konspekt.md#s6-4) · [П-12](8_2-mongodb-popravki.md#p-12) · [← вопрос](8_2-mongodb-voprosy.md#q-9)

<a id="a-10"></a>

### 10. Самая дорогая и пагинация

**Ответ:** `db.books.find().sort({ price: -1 }).limit(1)`. Без `sort` порядок документов не гарантирован, и «первый» — случайный. Третья страница по 10: `find().sort({ title: 1, _id: 1 }).skip(10 * (3 - 1)).limit(10)`. Для длинной ленты большой `skip` медленный и страницы «съезжают» при новых сообщениях, поэтому берут «следующие 10 старше последнего показанного» — пагинацию по ключу.

**Подробнее:** [Конспект §7](8_2-mongodb-konspekt.md#s7) · [П-10](8_2-mongodb-popravki.md#p-10) · [Пример 2](8_2-mongodb-primery.md#ex-2) · [← вопрос](8_2-mongodb-voprosy.md#q-10)

## D. Изменение и связи

<a id="a-11"></a>

### 11. Устаревшие методы

**Ответ:** `updateOne` / `updateMany`, `deleteMany`, `deleteOne`. У новых методов количество затрагиваемых документов видно из названия; у старых оно зависело от опций (`multi`, `justOne`), и легко было изменить или удалить больше, чем нужно.

**Подробнее:** [Конспект §8](8_2-mongodb-konspekt.md#s8) · [П-7](8_2-mongodb-popravki.md#p-7) · [← вопрос](8_2-mongodb-voprosy.md#q-11)

<a id="a-12"></a>

### 12. `findOneAndUpdate`

**Ответ:** документ **до** изменения, с `price: 45` (в базе при этом уже `50`). Чтобы получить новую версию — опция `{ returnDocument: 'after' }`.

**Подробнее:** [Конспект §8.1](8_2-mongodb-konspekt.md#s8-1) · [П-7](8_2-mongodb-popravki.md#p-7) · [← вопрос](8_2-mongodb-voprosy.md#q-12)

<a id="a-13"></a>

### 13. Продажа без минуса

**Ответ:**

```js
db.books.updateOne({ _id: 1, stock: { $gt: 0 } }, { $inc: { stock: -1 } })
```

Условие на остаток стоит в фильтре, поэтому проверка и изменение — одна атомарная операция над одним документом. Если книги нет на складе, в ответе `matchedCount: 0`.

**Подробнее:** [Пример 1](8_2-mongodb-primery.md#ex-1) · [8_1 §5.4 атомарность](8_1-nosql-konspekt.md#s5-4) · [← вопрос](8_2-mongodb-voprosy.md#q-13)

<a id="a-14"></a>

### 14. Вложенные документы и соединения

**Ответ:** запрос `{ profile: { city: 'Brisbane' } }` сравнивает **весь** вложенный документ и требует точного совпадения полей и их порядка; у пользователя в `profile` есть ещё `age`. Правильно — точечная нотация: `find({ 'profile.city': 'Brisbane' })`. Соединять коллекции вручную не нужно и SQL для этого не обязателен: в MongoDB есть стадия агрегации `$lookup`.
