## A. Принципы

<a id="a-1"></a>

### 1. Расшифруй SOLID

**Ответ:**

- **S** — у модуля одна причина для изменения;
- **O** — открыт для расширения, закрыт для изменения;
- **L** — подтип можно подставить вместо базового типа без нарушения ожиданий;
- **I** — клиент не зависит от методов, которые не использует;
- **D** — зависимость от абстракций, а не от конкретных реализаций.

**Подробнее:** [Конспект §1](10_4-testable-code-konspekt.md#s1) · [← вопрос](10_4-testable-code-voprosy.md#q-1)

<a id="a-2"></a>

### 2. Одна причина для изменения

**Ответ:** три причины: как получать данные (API), правило отбора (требования магазина), как показывать (дизайн). Разделение: сервис или абстракция для загрузки, чистая функция для правила, компонент только связывает и показывает.

**Подробнее:** [Конспект §2](10_4-testable-code-konspekt.md#s2) · [Пример 1](10_4-testable-code-primery.md#ex-1) · [← вопрос](10_4-testable-code-voprosy.md#q-2)

<a id="a-3"></a>

### 3. Новый метод — это OCP?

**Ответ:** добавление метода — тоже изменение класса; каждый новый вариант поведения снова требует его правки. OCP — заранее заданная точка расширения: код принимает стратегию (функцию или объект с интерфейсом), новое поведение — новая реализация, использующий код не меняется. Пример: `sortProducts(list, strategy)` и новые функции-стратегии.

**Подробнее:** [Конспект §3](10_4-testable-code-konspekt.md#s3) · [П-2](10_4-testable-code-popravki.md#p-2) · [← вопрос](10_4-testable-code-voprosy.md#q-3)

<a id="a-4"></a>

### 4. Лисков или инверсия?

**Ответ:** описаны слабая связанность и инверсия зависимостей. Принцип Лисков — о поведении подтипов: объект подтипа можно использовать везде, где ожидается базовый тип, и программа остаётся корректной; подтип не усиливает требования, не ослабляет обещания и не бросает неожиданных ошибок.

**Подробнее:** [Конспект §4](10_4-testable-code-konspekt.md#s4) · [П-3](10_4-testable-code-popravki.md#p-3) · [← вопрос](10_4-testable-code-voprosy.md#q-4)

<a id="a-5"></a>

### 5. Подмена нарушает контракт

**Ответ:** принцип Лисков: подмена — подтип сервиса, но не соблюдает его контракт. Тест проверяет код, который работает с массивом, а в приложении придёт Observable — тест зелёный, приложение сломано.

**Подробнее:** [Конспект §4](10_4-testable-code-konspekt.md#s4) · [10_3 П-4](10_3-vitest-popravki.md#p-4) · [← вопрос](10_4-testable-code-voprosy.md#q-5)

## B. Применение

<a id="a-6"></a>

### 6. Большой сервис

**Ответ:** разделение интерфейсов: компонент зависит от маленькой абстракции с одним методом (`abstract class ProductReader { abstract list(): Observable<Product[]> }`), в приложении её связывают с сервисом провайдером, а подмене в тесте нужен только этот метод.

**Подробнее:** [Конспект §5](10_4-testable-code-konspekt.md#s5) · [Пример 1](10_4-testable-code-primery.md#ex-1) · [← вопрос](10_4-testable-code-voprosy.md#q-6)

<a id="a-7"></a>

### 7. `new Date()` в компоненте

**Ответ:** результат зависит от момента запуска: тест «5 мин назад» пройдёт только в определённую минуту. Исправление — инверсия зависимостей: абстракция `Clock`, в приложении `SystemClock`, в тесте объект с фиксированным `now()`.

**Подробнее:** [Конспект §6](10_4-testable-code-konspekt.md#s6) · [Пример 2](10_4-testable-code-primery.md#ex-2) · [← вопрос](10_4-testable-code-voprosy.md#q-7)

<a id="a-8"></a>

### 8. Инверсия зависимостей в Node.js

**Ответ:** роутер не импортирует базу сам, а получает коллекцию параметром — `createProductsRouter(col)`. В приложении передают настоящую коллекцию MongoDB, в тесте — поддельный объект с нужными методами.

**Подробнее:** [10_2, пример 2](10_2-mocha-primery.md#ex-2) · [← вопрос](10_4-testable-code-voprosy.md#q-8)

<a id="a-9"></a>

### 9. Признаки

**Ответ:** например: чтобы проверить правило, нужно поднимать сервер или отрисовывать шаблон; внутри кода создаются зависимости (`new Something()`, `new Date()`, прямой импорт базы); подмене приходится реализовывать методы, которые тестируемый код не вызывает.

**Подробнее:** [Примеры — признаки](10_4-testable-code-primery.md#ex-0) · [← вопрос](10_4-testable-code-voprosy.md#q-9)

<a id="a-10"></a>

### 10. `useExisting`

**Ответ:** он говорит DI: «когда просят `ProductReader`, отдай уже существующий экземпляр `ProductService`». Компонент зависит от маленькой абстракции, но в приложении работает тот же сервис, без второго экземпляра.
